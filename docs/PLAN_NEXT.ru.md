# ПЛАН НА ЗАВТРА — доказать, что KERN работает

Состояние на момент составления: `HEAD == origin/main == f23f7713` (аттестует `#497`), дерево чистое,
`ci-fast rc=0`, `known_fp = 0`, `#495` закрыт, релизный архив собран и проверен как клиент.

## Главный принцип такта

**После доделок задача не «добавить», а «доказать».** Сегодняшние зелёные гейты — это
самопроверка: инструмент проверяет себя своими же средствами. Доказательством работы
это не является, пока **независимый человек** не получит **те же числа** на **своей** машине
и на **незнакомом** коде. Всё ниже подчинено этому.

## P0. Репро-квитанция: доказать воспроизводимость (полдня)

Цель: один внешний прогон, который нельзя подделать.

1. `git clone` в **чистый** каталог вне рабочей папки (`/tmp/kern-repro`), **без** `~/.cache/kern`.
2. Прогнать `make ci-fast`, `make tour`, `make xray-precision`, `make xray-overflow-check`,
   `make audits`, `make pcc-offline-check`, `make verify-attestation` под **системным** `python3`
   (не `.venv`) — там, где это допустимо.
3. Записать: `rc` каждого гейта, время, версии (`python3`, `zig`, `gcc`), `uname -a`.
4. Результат положить в `docs/evidence/repro_<дата>.log` и **закоммитить** — это квитанция.
5. Приёмка: **все** перечисленные гейты `rc=0` на чистом клоне; расхождение с сегодняшними
   числами — **дефект**, а не «особенность окружения».

## P0. Recall-цена `#495` — ИЗМЕРЕНА (`#498c`, сделано)

Фикс `#495` сузил детектор inc/dec до прямолинейных путей. Его цена больше не
«документирована» — она ИЗМЕРЕНА:

1. `make svcomp-witness-check` после `#495`: **37 задач, 11 UNSAFE подтверждено внешним
   валидатором, 16 SAFE чисты на перебранных свидетелях, 0 ложных тревог, 0 недобора**
   (`docs/evidence/svcomp_after_495.log`).
2. `svcomp_baseline.py`: **TPR 1.00 / FPR 0.00** (10 из 10 unsafe, 0 ложных на 5 safe) —
   ровно как в `docs/evidence/svcomp_baseline.log`.
3. НО пробники показали реальную дыру: ПОСТОРОННИЙ `if (flag) {…}` до
   `int x = 2147483647; x++;` давал **0 находок** — сплошной запрет глушил ровно тот
   паттерн SV-COMP, ради которого детектор написан. Правило СУЖЕНО (`#498c`): находка
   гасится, только если УСЛОВИЕ ветвления/цикла упоминает переменную; мутации ловит
   отдельный счётчик записей. ИЗМЕРЕНО после: посторонний `if` -> **1 находка**,
   `if (x==10) return; x++;` -> **0**, `cmark_autolink.c` -> **0**.
4. Приёмка выполнена: число в `docs/LIMITS` (RU+EN) — измеренное, а не обещанное.

## P1. Доказательство на незнакомом коде — ИЗМЕРЕНО, ЦЕЛЬ НЕ ВЗЯТА (0.375)

СЛЕПОЙ ПРОГОН по трём репозиториям, которых никогда не было в кэше
(`docs/evidence/blind_p1_2026-11-07.log`): curl `155f6f76` (lib/), redis `5b69ba2c` (src/),
tigerbeetle `68958eb7` (src/); детерминированная выборка = первые 25 файлов по имени;
0 правок анализатора ДО прогона.

| корпус | файлов | функций | находок | TP | FP | precision |
|:--|--:|--:|--:|--:|--:|--:|
| curl/lib | 25 | 81 | 0 | — | 0 | н/д (обвинений нет, и шума нет) |
| redis/src | 25 | 552 | 7 | 3 | 4 | 0.43 |
| tigerbeetle/src | 22 | 187 | 2 (1 дубль) | 0 | 1 | 0.00 |
| **всего** | | | **9** | **3** | **5** | **0.375** |

КАЖДАЯ находка разобрана построчно в логе. Названы ТРИ корня (правка пока НЕ сделана):
A) ПОЛЕ СТРУКТУРЫ моделируется как константа (`s->flags`, `fe->mask`, `batch.status`), хотя оно
пишется выше в той же функции, ВЫЗВАННЫМ кодом или через указатель -> UNSAT на ДОСТИЖИМЫХ
ветвях -> ложный DEAD BRANCH (3 из 5 FP);
B) беззнаковые типы в детекторе ГРАНИЦ (`size_t` как знаковый; короткое замыкание `op[0]=='('`
не считается гардом непустоты) — 2 FP;
C) одна и та же находка печатается дважды (tigerbeetle).

ДАЛЬШЕ: дельта-минимизация каждого корня до <=15 строк, ДВУСТОРОННИЙ контроль в `xray-precision`
(FP -> 0 И TP остаётся найденным), затем повторный замер на тех же трёх SHA.

ПОВТОРНЫЙ ЗАМЕР ПОСЛЕ ПРАВОК (`#500`+`#501`), те же три SHA, тот же срез из 25 файлов:
curl 0 · redis 7 -> **4** · tigerbeetle 2 -> **0**; **TP 4, FP 0 -> precision 1.00** (порог взят
на этом срезе). Все четыре оставшихся — «UB в ДОМЕНЕ СИГНАТУРЫ» (ни один вызывающий в дереве
не передаёт `LONG_MIN`/`INT_MIN`/`oplen <= 0`), так и названы — в «баги» не переименованы. Один
вердикт ПЕРЕСМОТРЕН явно в логе (`ACLSetUser`: `oplen` — отдельный аргумент `ssize_t`, значит
`op[0]=='('` не доказывает `oplen >= 1`). Цены по recall не обнаружено (SV-COMP TPR 1.00 / FPR
0.00 без изменений). Добавлен двусторонний контроль: `precision_clean/field_guard_write.c`
(ловушка -> 0) и `precision_dead_field/dead_after_kind.c` (настоящая мёртвая ветвь -> ровно 1).

## P1. Публикация (Шаг 2 плана ROI — построено и под гейтом, релиз ждёт доступа)

   `kerna-dist-v<ver>.tar.gz` + `SHA256SUMS`, сверяет SHA-256 ДО распаковки,
   `./kerna --doctor`, затем считает `audit-delta` base->head: `rc=1` только на находках,
   внесённых ЭТИМ изменением, `rc=2` при деградации покрытия, `rc=3` при плохом артефакте.
2. `make action-check` доказывает шаги ИСПОЛНЕНИЕМ (локальный источник релиза `file://`,
   сеть не нужна): матрица 8 случаев + 7 отрицаний; `make action-check REAL=1` прогоняет 5 из
   них на РЕАЛЬНОМ 27-МБ архиве.
3. `examples/ci/kern-gate.yml` — образец для копирования; его входы сверяются с
   `action.yml` (неверный вход краснит гейт).
4. Публикация подготовлена в `.github/workflows/release.yml` (архив + `SHA256SUMS` на ОБА
   ассета + `action-check` ПЕРЕД публикацией). Самой публикации нужны `gh` и доступы, которых
   на этой машине нет; точная команда:

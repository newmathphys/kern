# ПЛАН НА ЗАВТРА — доказать, что KERN работает

Состояние на момент составления: `HEAD == origin/main == f23f7713` (аттестует `#497`), дерево чистое,
`ci-fast rc=0`, `known_fp = 0`, `#495` закрыт, релизный архив собран и проверен как клиент.

## Главный принцип такта

**После доделок задача не «добавить», а «доказать».** Сегодняшние зелёные гейты — это
самопроверка: инструмент проверяет себя своими же средствами. Доказательством работы
это не является, пока **независимый человек** не получит **те же числа** на **своей** машине
и на **незнакомом** коде. Всё ниже подчинено этому.

## P0. Репро-квитанция: доказать воспроизводимость (полдня)

Цель: один внешний прогон, который нельзя подделать.

1. `git clone` в **чистый** каталог вне рабочей папки (`/tmp/kern-repro`), **без** `~/.cache/kern`.
2. Прогнать `make ci-fast`, `make tour`, `make xray-precision`, `make xray-overflow-check`,
   `make audits`, `make pcc-offline-check`, `make verify-attestation` под **системным** `python3`
   (не `.venv`) — там, где это допустимо.
3. Записать: `rc` каждого гейта, время, версии (`python3`, `zig`, `gcc`), `uname -a`.
4. Результат положить в `docs/evidence/repro_<дата>.log` и **закоммитить** — это квитанция.
5. Приёмка: **все** перечисленные гейты `rc=0` на чистом клоне; расхождение с сегодняшними
   числами — **дефект**, а не «особенность окружения».

## P0. Recall-цена `#495` — единственное незакрытое измерение (2–3 часа)

Фикс `#495` сознательно ограничил детектор inc/dec прямолинейным путём. Цена **не измерена**.

1. Прогнать `make svcomp-witness-check` (длинный, в фоне) и сравнить с прошлой базой.
2. Если падение recall есть — уточнить правило: разрешать цикл, если переменная **в нём не
   меняется** (`for (…) { if (c) return; } x--;`), и снова замерить.
3. Приёмка: число в `docs/LIMITS` (сейчас там только «recall loss documented»), заменённое на
   **измеренное** значение.

## P1. Доказательство на незнакомом коде (день)

Курируемые корпуса (`QuixBugs`, `TheAlgorithms`, `cmark`, `DeepJIT`) больше не считаются
доказательством: их видели при разработке.

1. Свежие клоны **трёх** репозиториев, которых не было в кэше: `tigerbeetle` (Zig), `redis` (C),
   `curl` (C). Никаких правок в них.
2. Для каждого — `./kerna <path> --sample N` + **триаж КАЖДОЙ** находки вручную:
   TP / FP / N(неопределённость) / caller-guarded.
3. Считать **precision = TP / (TP + FP)** и опубликовать **вместе с FP**, а не только с TP.
4. Приёмка: `precision ≥ 0.90` хотя бы на двух из трёх корпусов; иначе — честная запись класса FP
   в `#495`-стиле (фикстура + счётчик), а не тишина.

## P1. Публикация: то, что уже готово (2 часа)

1. GitHub Release `v2.8.1`: `kerna-dist-v2.8.1.tar.gz` (27 МБ) + `SHA256SUMS` + аттестат.
2. `action.yml` (composite): скачивает релиз, гоняет `kerna` + `audit-delta` на PR, `rc=1` при
   новой находке, `rc=2` при ослаблении покрытия.
3. Приёмка: пример workflow в `examples/ci/` проходит на **тестовом** репозитории; без релиза
   `action.yml` **не публикуется** (обещание без артефакта — запрещено, урок `#497`).

## Дисциплина такта

1. Любое утверждение в отчёте — **с числом и командой**, которой оно получено.
2. Гипотеза проверяется **замером до правки** (за сегодня это трижды опровергло «очевидное»).
3. Ложное обвинение считается и называется; «зелено» без числа не считается результатом.
4. Печать (`make seal`) — только на чистом дереве, после зелёного `ci-fast`.

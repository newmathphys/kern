# KERN, применённый к KERN — самопроверка с дословным выводом

> Все блоки ниже скопированы из реального прогона. Сырые логи:
> `docs/evidence/self_verification/` (`run.log`, `xray_src.log`, `xray_tools.log`).
> Повторить: `make self-verify`, `make diff-equiv`,
> `python3 tools/scan_to_kern.py . -o /tmp/bridge.kern`, `./zig-out/bin/kernx graph`,
> `python3 tools/kern_contracts.py --xray src tools`.

## 1. Собственный контракт ядра

`make self-verify` проверяет контракты в `examples/self_verify.zig` — файле, где
инварианты самого проекта записаны как `@kern:`-контракты:

```
[PASS] remaining:     ДОКАЗАНО
       [PROOF VERIFIED] steps: 54 | premises bound: 3/3 | mp: 15 | rewrite (linear): 18 | farkas: 1 | trusted: 0 | holes: 0
[PASS] farkasNegLeZero: ДОКАЗАНО
       [PROOF VERIFIED] steps: 27 | premises bound: 3/3 | mp: 10 | rewrite (linear): 10 | farkas: 1 | trusted: 0 | holes: 0
[PASS] clampToPool:   ДОКАЗАНО
       [PROOF VERIFIED] steps: 50 | premises bound: 2/2 | mp: 9 | rewrite (linear): 17 | farkas: 2 | trusted: 0 | holes: 0
ИТОГО: доказано 3 | нарушено 0 | НЕ РЕШЕНО 0 | ЛОЖНЫХ ТРЕВОГ 0 | ВАКУУМНЫХ 0 | вне подмножества 0
```

`trusted: 0 | holes: 0` во всех трёх: DAG доказательства перепроверен собственным
чекером, доверенных шагов и дыр нет. Есть невакуумный can-fail кейс
(`self-verify`), который ломает контракт и требует, чтобы цель покраснела.

## 2. Все заявления репозитория — в один bridge-файл

```
$ python3 tools/scan_to_kern.py . -o /tmp/kern_bridge.kern
[OK] артефактов=557, утверждений=74, связей=276
```

Сканер обходит дерево и извлекает 74 заявления (файл на месте, тест на месте,
якорь цел, TODO) в манифест `.kern` — инвентарь не пишется руками.

## 3. Врата Истины по собственным заявлениям

```
$ ./zig-out/bin/kernc build /tmp/kern_bridge.kern -o /tmp/bridge.kimg
[OK] Образ собран: /tmp/bridge.kimg (631 объектов)

$ ./zig-out/bin/kernc verify /tmp/bridge.kimg
    контракт НЕ привязан -> e=0 (N): текст без машинного доказательства
    ... (повторяется для каждого заявления)
[i] ИТОГ: доказано 1, контрпримеров 0, без контракта 73,
    РАСХОЖДЕНИЙ С ЗАЯВЛЕННЫМ СТАТУСОМ 0
[i] e=1 выставляется ТОЛЬКО по вердикту решателя. Заявления без
    привязанного контракта остаются e=0 — это и есть честный статус.
```

**Это самый важный результат документа.** Из 74 заявлений, которые репозиторий
делает о себе, **73 получают `e=0`** — потому что это **проза**, а не машинные
контракты. Врата отказываются принимать собственный README за доказательство.
Ни одно заявление не противоречит объявленному статусу, а `e=1` выдаётся только
по вердикту решателя.

Инструмент, который не верит даже себе, — единственный, которому можно поручить
проверять чужой код.

## 4. Граф архитектуры ядра, построенный ядром

```
$ ./zig-out/bin/kernx graph --root src
узлов 88 | рёбер 70 | внешних 0 | SCC-циклов 0
```

88 модулей, 70 рёбер импорта, внешних рёбер нет (дерево замкнуто на `src/`),
и **ни одного SCC** — то есть циклических зависимостей между модулями нет.
Граф дополнительно сверяется с артефактом витрины целью `make graph-check`.

## 6. Рентген без аннотаций по собственной обвязке (Python)

```
$ python3 tools/kern_contracts.py --xray tools
[REPO SUMMARY] файлов 95 | функций проверено 676 / 918 (skipped 242) | находок 679
```

679 находок: **4 обвинения `[CRASH PATH]` и 660 кандидатов `[BOUNDS]`**.
Обвинение и кандидат — разные вещи, и они классифицируются отдельно.

### Четыре обвинения, с классификацией

| Функция | Утверждение | Вердикт |
| --- | --- | --- |
| `bucket_of` (`cache_avalanche_bench.py:67`) | `% buckets` при `buckets == 0` | **Реальный скрытый риск.** Модуль защищён (`if N == 0: sys.exit(2)`), а **функция** — нет: любой другой вызывающий с нулём упадёт. Это остаток дефекта #323, чья починка была сделана на уровне модуля. Намеренно **не заглушено**: инструмент сообщает правду уровня функции. |
| `div_ok` (`deal_contracts.py:62`) | `a // b` при `b == 0` | **Известное ложное обвинение**, класс #322: защита — `@deal.pre(lambda a, b: b != 0)`, то есть **декоратор**, а его анализатор не моделирует (он моделирует `if`/тернарные гарды — исправлено в #327). Файл — фикстура для проверки deal-контрактов. |
| `div_bad` (`deal_contracts.py:68`) | то же | Тот же класс; эта фикстура **и должна** быть неверной. |

### Почему кандидатов `[BOUNDS]` — 660

Запись `[BOUNDS]` означает, что анализатор увидел индекс, длина которого
**символическая**: ни литерала, ни условия `len(...)`, которое можно
использовать. Это **кандидаты**, и инструмент печатает их именно так, никогда не
повышая до дефектов. Они сосредоточены на функциях, обходящих коллекции
вызывающего (`main`, `render`, `body_smt`, `collect`, …). Чтобы превратить их в
вердикты, нужны инварианты циклов (CHC, подключённый к анализатору) — это
записано как открытая работа, а не заявлено сделанным.

## 7. Эквивалентность рефакторинга на своих примерах

```
$ make diff-equiv
[КОНТРПРИМЕР] amount = 1, res_old = 0, res_new = 2, balance = 1
ИТОГО: эквивалентных 0 | разошедшихся 1 | всего 1
[OK] расхождение обнаружено (rc=1) — доказательство не фиктивно

[EQUIVALENT] charge: рефакторинг математически эквивалентен на всём домене Z (пруф-чекер принял)
ИТОГО: эквивалентных 1 | разошедшихся 0 | всего 1
[OK] положительный контроль: EQUIVALENT, пруф-чекер принял (trusted)
```

Два направления в одной цели: **намеренно сломанный** рефакторинг обязан быть
пойман с конкретным входом, а идентичный — обязан быть доказан. Иначе проверка
была бы тавтологией.

## 8. Чего самоприменение НЕ доказывает

- **Это не доказательство корректности кода.** В собственном Zig ядра нет
  `@kern:`-контрактов, поэтому §5 сообщает «0 находок» по **тому подмножеству,
  которое смог разобрать** (129 из 377 функций) — остальные 248 пропущены, с
  причинами.
- **Это не звучивое покрытие обвязки.** §6 дал 679 кандидатов, из которых 3
  обвинения заведомо ложны (класс #322), а 1 — реальный скрытый риск. Ни одно из
  них не доказательство.
- **Это не доказательство доказательств.** `trusted: 0 | holes: 0` относится к
  **DAG доказательства**, а не к Z3, который остаётся доверенным компонентом
  (см. `docs/THREAT_MODEL.md`).
- **`e=0` на собственном README — ожидаемый результат, а не провал.** Он говорит,
  что заявления — проза. Чтобы получить `e=1`, каждому нужен машинный контракт.
- **Гейт свидетельств проверяет `RC=` только у логов верхнего уровня.** Из 49
  логов в подкаталогах 21 не несут `RC=` — большинство это сырые транскрипты
  моделей (данные, а не прогоны команд), но два класса пока не разделены. Это
  записано здесь, а не «починено»: приписать транскрипту `RC=` значило бы
  выдумать значение.

## 9. Что самоприменение устанавливает

| Свойство | Свидетельство |
| --- | --- |
| Инварианты проекта доказаны его же чекером | §1, `trusted: 0 \| holes: 0` |
| Каждое заявление в дереве извлечено машинно | §2, 557 артефактов / 74 заявления |
| Врата **не** принимают прозу за доказательство | §3, `e=0` у 73 из 74 |
| Циклических зависимостей в ядре нет | §4, 0 SCC |
| На своём Zig анализатор молчит там, где у него нет свидетельств | §5, 0 находок, 248 пропусков с причинами |
| Где обвиняет — проверяемо, где ошибается — мы это называем | §6, 4 обвинения классифицированы |
| Проверка эквивалентности умеет и ловить, и доказывать | §7, оба направления |

# ГРАНИЦЫ KERN — ЧЕГО ОН **НЕ** ДОКАЗЫВАЕТ

Этот документ существует, потому что честность продаёт лучше маркетинга: у каждого
верификатора есть границы, и разница только в том, названы они или спрятаны. Здесь
перечислены ВСЕ измеренные границы с числами и способом проверить каждую.

## 1. `PROVEN` ≠ «доказательство проверено»

Слово `PROVEN` в таблице `audits/EVIDENCE.md` — это вердикт **решателя**. Пруф-чекер
проверяет вывод ОТДЕЛЬНО, и рядом с каждым `PROVEN` обязан стоять счётчик доверенных
шагов (дефект `#474`):

| Метка | Значение |
|:--|:--|
| `trusted 0` | решатель и чекер согласны — доказательство проверено |
| `[PROOF PARTIAL] trusted N` | ЧЕСТНАЯ ГРАНИЦА: N шагов опираются на аксиомы решателя |
| `trusted ?` | чекер счётчик не сообщил (`ДОКАЗАНО (допущено)` — более слабая претензия) |

**Измерено на корпусе:** 44 формулы → **13** `trusted 0`, **11** `PARTIAL`, **20** без
счётчика. Для `QF_BV` частичность принципиальна: доказательство опирается на аксиомы
бит-бластера `k!` — свободную недоказуемую константу, поэтому строгая оффлайн-проверка
без решателя **невозможна**. ИЗМЕРЕНО на `hex_index_deepjit_hex_hi`: `ДОВЕРЕННЫХ 15`.

**Следствие для «proof-carrying artifacts»:** они таковы для LIA и булевых инвариантов;
для BV — `PARTIAL` с названным числом. Путь вперёд — решатель с полными DRAT/LFSC
сертификатами (cvc5 / Bitwuzla), а не Z3-аксиомы.

## 2. Вещественная арифметика не моделируется (QF_FP)

`f32`/`f64`/`float`/`double` **не** поддерживаются: функции с ними получают НАЗВАННЫЙ
пропуск `вещественная арифметика (f32/f64) — модель QF_FP не поддерживается` (`#472`).
До этой правки они молча уходили в `i64`, и `debt / equity` (f64/f64) объявлялось
паникой деления на ноль, хотя IEEE-754 даёт `inf`/`NaN`. **Измерено:** 138 таких
пропусков на `TheAlgorithms/Rust`, 4 на `DeepJIT`, 6 на собственном Zig-ядре KERN.

## 3. Инварианты циклов не моделируются (Белнап N)

`while`/`for` разбираются ОДНОЙ итерацией с условием цикла как гардом. Полный инвариант
(нужен CHC/Horn) не выводится, поэтому:
* индекс, зависящий от переменной, изменённой в цикле, даёт `[BOUNDS UNKNOWN]` —
  это **N** (неопределённость), а не находка (`#315`, `#473`);
* находки внутри тела цикла не обвиняются без свидетеля.

## 4. Известные ложные обвинения считаются, а не прячутся

`#476` (ОТКРЫТ): `len(<литерал>)` в гарде не связывается с литеральной длиной, поэтому
`data = [1,2,3,4]; if 0 <= i < len(data): return data[i]` обвиняется с контрпримером
`i = -1`. Функция живёт в `tests/fixtures/precision_known_fp/`, гейт `make xray-precision`
требует там РОВНО одну находку и покраснеет, когда дефект исправят.

**Точность на чужом коде измеряется машинно** (`#475`): `precision_clean` → 0 находок,
`precision_buggy` → 5/5, внешний корпус `QuixBugs/correct_python_programs` сверяется с
названной базой (**21** ложное обвинение на 50 корректных программ, цель 0). Это долг,
названный числом.

## 5. Межпроцедурные инварианты не проверяются

Длина, ненулевость и диапазон, обеспеченные ВЫЗЫВАЮЩИМ, не моделируются (`#200`): если
`len > 0` гарантирован снаружи, делитель всё равно считается подозрительным — но мы
НЕ обвиняем (пропуск безопаснее ложного обвинения).

|:--|:--|

| подпроцесс без таймаута | `make spawn-check`, `make spawn-selftest` |
| память подпроцессов | `make audits-mem-check` |
| арифметика корпуса | `make audits` |

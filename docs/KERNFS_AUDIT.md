## Что тестировалось

- `tools/build_kernfs.py` — билдер образа `.kimg`
- `src/core/kernfs.zig` — движок (mmap, `ls`, `cat`)

## 🔴 Ошибки (8)

### 1. `build_kernfs.py` **не разбирается вообще**

```
line 21
  {"path": b"src/core/memory.zig", ..., "content": b"pub fn alloc() void { // Выровнено по 64 байта }\n"},
                                                         ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
SyntaxError: bytes can only contain ASCII literal characters
```

Байтовый литерал `b"…"` не может содержать кириллицу. Скрипт **падает до запуска**.
Правка: `"…".encode("utf-8")` — после неё образ собирается (628 байт).

### 2. Файл `kimg_reader.zig` **отсутствует в спецификации**

`kernfs.zig` и `main.zig` импортируют `core/kimg_reader.zig`, но его текст не
приведён. Без него **ничего не собирается**. Написал по формату билдера
(`"<8s H H I I I Q Q Q Q Q 32s 32s"` = 128 байт) — раскладка сошлась байт в байт.

### 3. Показанный в документе вывод `ls` — **выдуман**

| Файл | Документ | Фактически |
|:--|--:|--:|
| `src/core/memory.zig` | 55 | **65** |
| `claims/L0_AlignmentInvariant.kern` | 32 | 32 ✅ |
| `PROJECT_CANONICAL_SPEC.kern.md` | 39 | **30** |

Причина: кириллица в UTF-8 занимает **2 байта** на символ, а не 1. Ожидаемые
числа в документе получены без учёта кодировки.

### 4. Пути `ls` и `cat` **не совпадают** — копировать нельзя

```
ls  показывает:  /src/core/memory.zig        ← с ведущим слешем
cat требует:      src/core/memory.zig        ← без слеша
```

```
$ kernc cat build/release_v1.kimg /src/core/memory.zig
Файл '/src/core/memory.zig' не найден в виртуальной ФС.
```

Пользователь копирует путь из `ls` — и получает «не найден».

### 5. Образ **не проверяется вообще** — вредоносный файл роняет процесс

| Подмена в образе | Результат |
|:--|:--|
| `object_count = 1 000 000` | **SIGSEGV (134)** |
| `payload_offset` вне файла | **SIGSEGV (134)** |
| `path_offset = 999999` | Debug: паника; **ReleaseFast: SIGSEGV (139)** |
| испорченный `magic` | **игнорируется**, вывод как у нормального |
| испорченный `header_size` | **игнорируется** |

`magic` не сверяется, границы не проверяются. В **ReleaseFast** проверки границ
Zig отключены — вместо понятной паники **сырой segfault**.

### 6. **`digest` (SHA-256) не проверяется никогда**

Подменил содержимое файла в образе, `digest` в дескрипторе оставил старым:

```
SHA-256 в дескрипторе совпадает с новым? False
$ kernc cat attack_digest.kimg src/core/memory.zig
PUB FN HACKED() void { } Выровнено по 64 байта }
```

**Подделанный контент выдан без единого предупреждения.** Поле `digest`
занимает 32 байта в каждом дескрипторе, но **не используется** — это украшение.

### 7. **Путаница путей** — два объекта могут указывать на один путь

Подменил `path_offset` второго объекта на 0:

```
 [source  ] | 65  | /src/core/memory.zig      ← объект 0
 [claim   ] | 32  | /src/core/memory.zig      ← объект 1: ТОТ ЖЕ путь!
 [manifest] | 30  | /PROJECT_CANONICAL_SPEC.kern.md
```

`cat` вернёт содержимое первого совпадения — то есть **чужой файл**. Проверки
уникальности путей нет.

### 8. «Без распаковки» — **пустое утверждение**

`compressed_size` и `compression_codec` в дескрипторе **не используются**:
`cat` берёт `uncompressed_size` и делает срез. Сжатия нет вовсе, поэтому
«распаковывать» нечего. Заявление технически верно и содержательно пусто.

## Как воспроизвести

```bash
python3 tools/build_kernfs.py          # → SyntaxError
# после правки: build/release_v1.kimg (628 байт)
uv pip install --python ./zigv/bin/python ziglang==0.13.0
zig build && ./zig-out/bin/kernc ls build/release_v1.kimg
./zig-out/bin/kernc cat build/release_v1.kimg src/core/memory.zig
```

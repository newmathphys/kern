# KERN — Roadmap (ветка `v2.5-dev`)

> **Правило проекта.** Каждый пункт приходит с **can-fail кейсом** (`tools/canfail.py`
> доказывает, что проверка СПОСОБНА покраснеть) и **проверяемым числом** из команды этого
> репозитория. Фича без проверки, способной упасть, считается здесь дефектом, а не фичей.
> См. [`CONTRIBUTING.md`](../CONTRIBUTING.md).

**Статус файла.** Локальный черновик ветки `v2.5-dev`. Публичный `main` заморожен на
`28e6bb9` (релиз `v2.4.0`); в `origin` ничего не выгружается.

### 0.4 Вывод, меняющий объём работ

> Разрыв не «нет математики», а **«движки есть — нет фронтенда, который подаёт в них
> произвольный файл»**. `kernc audit` прогоняет пять теорий на **захардкоженных** примерах
> (`line_10_non_negative`, `x*8`). Значит `--xray` — это **применить существующие движки**
> к разобранному файлу, а не строить теории с нуля.

## 1. Поправки, без которых план станет самообманом

| # | Как звучит в списке | Что на самом деле и что делаем |
|:--|:--|:--|
| **C1** | 39 — «охота за настоящими багами» прогоном по Zig stdlib и `.venv` | **Измерено: 0.** В сторонних проектах аннотаций `@kern:` нет, в поддерживаемое подмножество попадало 0 из 715 функций. Автопрогон даёт таблицу нулей. Работает другое (и уже работает): `--infer-requires` + **прицельные тень-контракты**, проверенные глазами — GPA `isAligned`, TigerBeetle `div_ceil`, musl `abs`, zlib `zcalloc` |
| **C2** | 13 — `--xray` находит мёртвые ветки и тавтологии в любом коде | Нужны path conditions по всему CFG; парсер моделирует линейные `if/else` в одном теле. Плюс «мёртвая ветка» для неразмеченного кода = «недостижимо при **любом** входе». Обязан печатать «проверено N из M, M−N вне подмножества» и формулировать как «недостижимо в смоделированном домене» |
| **C3** | 22/23/30 — float, строки, SQL для security-заявок | `QF_S`/`QF_FP` — это **теории**: ложный PROVEN в security-заявке хуже отсутствия проверки. Float — только детектор краш-путей; `--verify-sql` — проверка **предикатов политики** (RBAC/IAM/RLS), а не семантика SQL-движка |
| **C4** | 34 — `@kern:secret` как «самое сложное» | **Хорошая новость:** `noninterference.zig` уже есть, а `--diff-equiv` — та же форма (две копии тела + связка). Работа = подключить к экстрактору, не изобретать |
| **C5** | 28 — гонки, double spend, TOCTOU | Настоящая конкурентность требует модели перемежений и памяти; подмножество чисто последовательное. Честная версия — **последовательное** свойство двух вызовов. Гонки не заявляем |
| **C6** | 7 — Хэмминг-кодирование `e` («против космических лучей») | Это **не проверяемое** свойство, DO-178C такого не требует, а тип `e` тянется через все вызовы ядра. Делаем как **изолированный примитив** с тестами и **без заявления о радиационной стойкости** |
| **C7** | 6 — «UNSAT-core даёт точную виновную строку» | Для **нарушенного** контракта запрос SAT — ядра не применимы. Звучимый механизм — **assumption literals** (`check-sat-assuming`): минимальный набор предположений, при котором всё ещё SAT. Это **уровень ветки**, а не «точная строка» |
| **C8** | 9 — Proof-Carrying `.kimg` | Замерено: доказательство — от 3.5 КБ до **623 КБ** на обязательство. Нужна политика: хранить при размере ≤ бюджета, иначе `digest` + перевывод |
| **C9** | 40 — WASM «доказывать в браузере» | В `wasm32` уедет **только пруф-чекер** (Z3 — внешний процесс). Нужна развязка `proof_check.zig` ↔ `z3_bridge`/`unsat_core`. Оценка «~40 КБ» не измерена |
| **C10** | 40 — «Lean 50 теорем» одним блоком | Теорема обязана быть привязана к **конкретному поведению кода** (как в работе по #118). Теоремы приезжают вместе со своей фичей |
| **C11** | 36/37/38 — Firewall, RAG, RLVR | Это **продукты поверх** KERN. `guardrail_proxy.py` уже есть как прототип. Расширяем прототипы, не объявляем фичами ядра; «демон в реальном времени» конфликтует с текущим «вне рамок» — решение нужно отдельное |

## 3. Определение готовности (на каждый пункт)

1. **can-fail кейс** в `tools/canfail.py` — проверка способна покраснеть.
2. **Проверяемое число** из команды репозитория.
3. Строка в [`CHANGELOG.md`](../CHANGELOG.md) под `[Unreleased]`.
4. Запись в реестр дефектов (`docs/CAPABILITY_STATUS.md`), если что-то вскрылось.
5. **Ни одной новой цифры** в таблицах «Measured / Core health» до фактического замера.

## 4. Коммиты и границы

* Ветка `v2.5-dev`, **один чистый локальный коммит на эшелон**.
* **В `origin` — ничего.** `main` и `v2.4.0` остаются ровно на `28e6bb9`.
* Перед каждым коммитом: `zig build test` / `test-next` / `test-fault`, затем гейты
  (`registry`, `evidence-gate`, `canfail`, `gen_test_catalog --check`, `svg-check`).

## 5. Что остаётся на операторе

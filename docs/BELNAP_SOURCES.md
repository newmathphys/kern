# Формальная база KERN: источники и сверка с кодом

> **Зачем документ.** Каждая строка KERN, управляющая допуском, опирается на
> конкретный результат из литературы. Здесь — что именно, где в коде и **чего
> в KERN нет**. Утверждения проверяются машинно: `make citations-check`.

## §0 Как читать статусы

| Статус | Что означает | Где можно использовать |
|:--|:--|:--|
| `verified` | открыта страница издателя/Crossref, поля сверены | §1–§5 как основание |
| `secondary` | подтверждено списком литературы другой работы; DOI не открывался | §1–§5 с пометкой |
| `unverified` | не подтверждено | **только §7**, как «требует проверки» |

Данные: `docs/references.bib` (25 записей, ключи `§REF:<key>`) и
`docs/references.lock.json` (снимок полей). `citations-check` падает, если:
ключ не существует; `§REF:` на `unverified` встречается в §1–§6; у записи нет
DOI/ISBN/arXiv; ссылка `файл:строка` или теорема Lean не существует; EN-версия
не содержит того же набора ключей.

## §1 Первоисточники

- **§REF:belnap1977useful** — четыре значения `4 = P({T,F})`, два порядка (`≤t`, `≤k`),
  мотивация «локальный конфликт не должен заражать базу». Основание для B4, `joinK`, врат.
- **§REF:dunn1976intuitive** — реляционная семантика FDE: `A ρ 1` и `A ρ 0` как
  независимые свидетельства; отсюда пара `(p, n)`.
- **§REF:ginsberg1988** — термин «бирешётка» и условие перемежаемости операций.
- **§REF:fitting1991** — монотонность вывода по `≤k` и неподвижная точка; обоснование,
  что накопление свидетельств не «перезаписывается последним прогоном».
- **§REF:fitting1994** — K3/LP как фрагменты B4 (отсечение `B` / `N`).

## §2 Бирешётки и решётки де Моргана

- **§REF:arieli1996** — логические бирешётки и бифильтры: формальная рамка для `{T,B}`
  как «содержащих истину».
- **§REF:font1997** — B4 и решётки де Моргана: почему `∧, ∨, ¬` образуют корректную алгебру.
- **§REF:rivieccio2011residuated** — резiduированные бирешётки: пара `⊔/⊓` как остаток.
- **§REF:shramko2005sixteen** — 16-значные логики; в KERN не используется, но объясняет
  происхождение формулы «how a computer network should think» (см. §7).

## §3 Обобщённые значения

- **§REF:shramko2011truth** — трирешётка `16₃` (порядки истины, ложности, информации).
  В KERN **не реализована**; фиксирует границу: у нас два порядка, не три.
- **§REF:omori2017forty** — обзор 40 лет FDE: что считается «стандартной» семантикой.
- **§REF:omori2019newessays** — современная антология: расширения BD, коннексивные логики.

## §4 Русская школа

- **§REF:karpenko2017four** — расширения BD и DM4, решётки функциональных расширений.
- **§REF:pavlov2005** — операторы утверждения истинности/лживости: сведение 4-значной
  семантики к метаязыку (идейная параллель с `e = 1` только при `T`).
- **§REF:shramko2017relatives** — родственники FDE (exactly true, non-falsity).
  Полезно для §6: KERN **не** различает «точно истинно» и «неложно» — он строже.

## §6 Чего в KERN НЕТ (и это заявлено честно)

| Не реализовано | Почему | Где зафиксировано |
|:--|:--|:--|
| **Конфляция** `~(t,f) = (1−f, 1−t)` | полный набор связок B4 требует `~`; сейчас есть только `¬` | Фаза 1 плана |
| **Трирешётка `16₃`** | KERN работает с B4; третий порядок не нужен для контрактов | §REF:shramko2011truth |
| **K3 / LP как режимы** | B4 — их надмножество; отдельные режимы не дают новых вердиктов | §REF:fitting1994 |
| **Абдукция** | гипотезы не единственны и не звучат; в KERN — только read-only отчёт (Ф6.3) | `docs/PLAN_v2.5.3.md`, §REF:bienvenu2026abductive |
| **Модальности** (essence/accident) | нет добавленной выразительности: `∀/∃` уже есть | `docs/PLAN_v2.5.3.md`, §REF:petrukhin2026essence |
| **First-order интуиционистский BD** | KERN — пропозициональный SMT-контур | §REF:niki2026firstorder |
| **Отзыв свидетельства** как операция решётки | у монотонного `⊔` нет обратной операции; `retract` — расширение (пересчёт набора) | Фаза 2 плана |
| **`trusted: 0` на Z3** | proof-checker не доверяет ничему, но Z3 — в TCB | `docs/THREAT_MODEL.md` §3 |

## §8 Как воспроизвести проверку

```bash
make citations-check                     # ключи, ссылки файл:строка, теоремы, статусы
python3 tools/citations_check.py --json  # машиночитаемо
```

Поиск источников:

```
"<точное название>" + издательство   → link.springer.com / sciencedirect / OJS
api.crossref.org/works?query.bibliographic=<название+автор>&rows=1
arxiv.org/abs/<id>                    → препринты (проверять журнальную версию)
```

Правило: **`verified` ставится только после открытия страницы издателя.**
Список, помеченный «проверено», без такой процедуры уже дважды содержал ошибки (см. §7).

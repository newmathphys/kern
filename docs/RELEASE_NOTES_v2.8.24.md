# KERN v2.8.24 — саботаж не уезжает в коммит

Релиз закрывает пять дефектов, каждый найден **измерением**, а не догадкой. Три из них — в
собственных воротах проекта.

## `#627`/`#628`: прерванный `canfail` попадал в коммит

Стенд `canfail` доказывает, что проверки способны падать: он **временно** вставляет в исходники
маркер `ЛОМАЕМ` и заведомо неверный код. Если стенд прервать, диверсия остаётся в дереве.

**Измерено:** три закоммиченные диверсии.

| Файл | Что лежало в коммите | Эффект |
|:--|:--|:--|
| `src/core/kimg_reader.zig` | `return MerkleRootMismatch; // ЛОМАЕМ: всегда несовпадение` | сборка падала: `error: unused local constant` |
| `src/core/eq2.zig` | `… // ЛОМАЕМ: ~ больше не инверсия` | то же |
| `src/core/kimg_reader.zig` | `… // ЛОМАЕМ: без проверки` | **тихо убирало проверку границ таблицы объектов** |

Все три восстановлены из версии до инъекции. Добавлен предохранитель
`tools/sabotage_guard.py` (цель `make sabotage-guard`, этап в `ci-fast`, реестр `CHECK`):

* `R1` в `HEAD` нет маркеров диверсии (`ЛОМАЕМ` / `SABOTAGE`) в `src/`;
* `R2` `tools/canfail.py` — **названное** исключение (стенд обязан знать маркеры);
* `R3` гейт **умеет падать**: файл с маркером во временном дереве даёт `rc=1`.

Скан идёт **только по коммиту** (`git grep HEAD -- src`): во время прогона другие стенды законно
вставляют и снимают маркеры — проверка рабочего дерева давала ложное срабатывание (тоже измерено
и исправлено в тот же день).

## `#626`: `seal` считал грязью свои же артефакты

`dirtyTree=true` появлялся на идеально чистом старте: в расчёт попадали `kern.intoto.*` и
перегенерируемый `docs/evidence/all_capabilities_real_*.log`, которые `seal` сам и создаёт.
Из-за этого цикл «seal → commit → seal» не сходился, а `verify-attestation` вечно падал.

Теперь собственные артефакты исключены **поимённо** (список печатается), остальное считается.
Проверено на живом прогоне:

```
[OK] kern.intoto.jsonl — субъектов 1, коммит ca277e09ae9f, dirty=False
АТТЕСТАТ ВАЛИДЕН → АТТЕСТАТ ПРОВЕРЕН (внешним ключом)
```

## `#624`: якорь `canfail` был прибит к версии

Кейс `N13` подменял **жёсткую** строку `releases/download/v2.8.3` в README. После релиза 2.8.23
якорь исчез → CI красный. Локальный `ci-fast` был зелёным, потому что `canfail` в него не входит —
именно этот разрыв и дал крестик. Версия теперь читается из `server.json`, кейс остаётся
способным упасть.

## `#625`: `--diff-equiv` падал на реальном файле

Аудит истории `archetype-py` (клонированной с `--depth 80`) вскрыл
`TypeError: NoneType is not a container` на 1033-строчном файле: тело функции не извлеклось, а код
проверял `"_havoc_" in ba`. Теперь `[SKIP] тело не извлеклось` вместо трейсбека.

Честный результат той же попытки: после фикса обе реальные пары коммитов дали `НЕ СРАВНИМО` —
произвольные коммиты редко содержат одну и ту же функцию в одном подмножестве. «Слепой аудит
refactor-коммитов» требует **отбора пар** (`docs/TIME_MACHINE_BENCHMARK.md`).

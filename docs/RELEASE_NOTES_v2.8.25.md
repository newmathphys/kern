# KERN v2.8.25

Релиз про **слепоту, которую никто не замечал**, и про три класса арифметики C,
которые детектор границ путал в один.

## Главное: `#501b` — stdint, integer promotion и unsigned wrap

Детектор границ (`--xray`) теперь различает три физически разные реальности при
одном и том же предикате пробоя (`index_expr < 0` в Int-модели):

| Класс | Типы | Что происходит на самом деле |
|:--|:--|:--|
| **A** знаковые | `int`, `int8_t…int64_t`, `ssize_t`, `ptrdiff_t`, `i8…i64` | прямой отрицательный индекс |
| **B** узкие беззнаковые **в C/C++** | `uint8_t`, `uint16_t`, `unsigned char/short`, `typedef uint8_t u8` | **integer promotion** (C11 §6.3.1.1): `(uint8_t)0 - 1 == -1` → `b[-1]`, чтение **до** буфера |
| **C** широкие беззнаковые + **все** беззнаковые Rust/Zig | `uint32_t`, `uint64_t`, `size_t`, `u8…u64`, `usize` | unsigned underflow / wrap-around: `SIZE_MAX` или panic |

Причина, почему это не работало: `_c_type_key()` возвращал ключ `uint8_t`,
которого нет в `_CLIKE_RANGES`, и параметр **молча выпадал** из `ranges` — на
выходе честный, но бесполезный скип «тип индекса НЕИЗВЕСТЕН».

Двусторонние регрессии в `make xray-check` — **7/7**: без гарда обвиняем, под
`if (i < 1)` молчим; `u8` в Rust **не** получает диагноз promotion; `typedef
uint8_t u8` в `.c` остаётся классом B. На чистых корпусах (cmark-gfm, C-like
B2, `#318`) — **0 ложных срабатываний**: предикат один, поэтому безобидный
`buf[i]` при `i >= 0` не обвиняется никогда.

## Демонстрации пользы (самопроверяемые, `rc=0`)

- `examples/iam_belnap_conflict.py` — две облачные политики сталкиваются лбами:

  pytest их не видит. Фикстуры создаются в `tempfile.TemporaryDirectory()` —

  `fee_down` **REFUTED** контрпримером, `fee_up` **PROVEN** с `trusted: 0`.

- `#650` кейс `mutation-lock` был **вакуумным** в изоляции `#630`: в git-worktree
  `.git` — файл-указатель, запись маркера падала молча. Кейс и чекер берут путь
  через `git rev-parse --git-dir`.
- `#649` `CASE_TARGET` для трёх новых кейсов (класс #356) + карта возможностей:
  210 целей, **0 неклассифицированных**.

  **комментариях** — гейт сиротства искал подстроку. Теперь подключены
  по-настоящему; парсер сирот видит только `make [-флаги] <target>` без
  комментариев, причём `#` срезается с учётом кавычек.
- `#646` три новых canfail-кейса: `sabotage-guard`, `orphan-gates`, `tools-laws`
  (последний ломает **тело** функции под целым контрактом — проверяется код, а
  не спецификация).
- `#645` AST-аудит правил canfail слит в `sabotage_guard`: 207 литеральных правил,
  **0 диверсий** в HEAD, **0 устаревших якорей**.
- `#644b` `"$(PYTHON)"` взят в кавычки во всех **208** рецептах Makefile (путь с
  пробелом `Рабочий стол` давал `make: /home/.../Рабочий: Нет такого файла`).
- `#641` `examples/ci/kern-gate.yml` стал **14-й поверхностью версии**: пиннинг
  образца дрейфовал (v2.8.3) и ронял `action-check` на шаге гейта **перед**
  публикацией — то есть блокировал релизы. Теперь дрейф ловится гейтом версий.

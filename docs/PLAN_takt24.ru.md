## 2. Три дефекта

* **`#471`** — гард терялся в ТРЁХ местах: (а) Python: скан на `ast.If` обходил всю
  конструкцию, включая `orelse`, с прямым гардом вместо `(not cond)`; (б) C-like: тело
  `while` анализировалось без условия цикла; (в) C-like: ветвь `else` не получала
  отрицания вовсе.
* **`#472`** — `f32`/`f64` молча уходили в целочисленную модель → ложная «паника деления
  на ноль». Теперь — названный пропуск: QF_FP не моделируется.
* **`#473`** — `[BOUNDS UNKNOWN]` (Белнап N) считался находкой под второй меткой.

## 3. Чему научил сам такт (записать, чтобы не повторять)

**Первая версия `#471c` была ошибочной и ГЛУШИЛА настоящие находки.** Она ДОБАВЛЯЛА
`(not cond)` к пути, где прямой `cond` уже лежал (`if_blocks` регистрирует `if/else`
ОДНИМ блоком). Получалось `cond ∧ ¬cond` = UNSAT, и из отчёта исчез
`modular_exponential` — настоящее `modulus == 0`. Поймано сверкой «до/после» по
функциям, а не по счётчику. Правило: **правка гарда обязана проверяться списком
находок, а не только их числом.**

## 6. Позиционирование (решено на этом такте)

Не «антивирус» (он обещает «поймает всё», а точность пока 56 % → после такта ≈ 90 %) и
не «пруф-движок для всех». Лицо: **шлюз допуска для кода, написанного ИИ** — «можно ли
этот код пускать дальше» с четырьмя состояниями Белнапа (`T/F/B/N`) и артефактом.
Дифференциатор B2B: **proof-carrying artifacts** — но ЧЕСТНО: для LIA/булевых; для
QF_BV — `[PROOF PARTIAL]` с названным числом доверенных шагов.

## 🏆 Главный результат: сьют нашёл **НАСТОЯЩУЮ уязвимость**

### SEC-01: «Offset Bomb» — **подтверждена, эксплуатируема**

Тест ставит `object_table_offset = MAX_U64 − 10`, `size = 100`. Без безопасной
арифметики `offset + size` **переполняется**:

```
offset      = 18446744073709551605   (MAX_U64 − 10)
size        = 100
истинная сумма = 18446744073709551705  ← переполнение
завёрнутая     = 89
file_size      = 1024
проверка "89 > 1024" → ЛОЖЬ → ГРАНИЦА ПРОЙДЕНА
```

**Проверено на деле:**

| Режим | Поведение ДО правки | Результат |
|:--|:--|:--|
| **Debug** | `panic: integer overflow` | паника |
| **ReleaseFast** | **образ ПРИНЯТ**: возвращён `KimgHeader{ .object_table_offset = 18446744073709551605, ... }` | 🔴 **обход защиты** |

**В ReleaseFast вредоносный образ проходил проверку целостности.** Это ровно та
атака, от которой тест и должен защищать.

**Исправлено** (`std.math.add` + отдельный код `OutOfBoundsOffset`) — после правки
SEC-01 **проходит в обоих режимах**.

> Это единственный тест сьюта, который нашёл реальную уязвимость. Ценность — высокая.

## 🔴 AI-01: заявленное отклонение **не происходит**

Тест кладёт в сертификат текстовую строку `"trust me bro, code is valid"` (26 байт)
и ожидает `FakeWitnessRejected`.

**Факт:**
```
AI-01: expected error.FakeWitnessRejected,
       found AdmissionResult{ .eq2_status = Eq2.N, .e_value = 0 }
```

Причина — в `runTrustedChecker` проверяется **только длина**:

```zig
if (payload.len < 8) return GateError.FakeWitnessRejected;  // 26 >= 8 -> пропущен
const magic = payload[0];   // 't' = 0x74 -> ни 0xAA, ни 0xBB, ни 0xCC
return .Unknown;            // -> eq2 = N, e = 0
```

**Строка ≥ 8 байт не отвергается с ошибкой** — она молча даёт `N` (e=0).

Честная оценка: **безопасность не нарушена** (код НЕ допущен, e=0), но
**заявленный механизм не тот**. Утверждение «*отбрасывает фейк, потому что
длина меньше 8 байт*» верно лишь для коротких строк.

## 🔴 AI-03: ошибка **в самом тесте** (маска политики)

```
AI-03: expected error.PolicyViolation, found error.UntrustedChecker
```

```zig
.checker_id = 1,
.allowed_checkers = 1,     // <-- выглядит как «разрешить checker 1»
```

Но маска считается как `1 << checker_id`, то есть `checker_id=1 → бит 1 → 2`:

```
checker_id=1 -> маска = 1<<1 = 2
allowed_checkers = 1 (бит 0)
1 & 2 = 0 -> ОТКАЗ (UntrustedChecker) — до анти-вакуумной проверки дело не доходит
```

**Чтобы разрешить `checker_id = 1`, нужно `allowed_checkers = 2`.**

Проверка: с `allowed_checkers = 2` **AI-03 проходит**, а AI-01 всё равно падает.
Значит AI-03 — ошибка теста, AI-01 — расхождение кода и заявления.

> Отдельно: сам маппинг «номер → бит» сдвинут на единицу относительно интуиции
> (`1` ≠ «checker 1»). Это ловушка для того, кто будет настраивать политику.

## Замечание к MATH-02

Тест назван «**De Morgan's Laws**», но **законы де Моргана не проверяет**.
Внутри — два изолированных утверждения (`andT(T,F)==F`, `notB(B)==B`).
Заявленная тождественность `NOT(A AND_T B) == NOT(A) OR_T NOT(B)` **не тестируется**,
хотя `orT` в сьюте даже не используется.

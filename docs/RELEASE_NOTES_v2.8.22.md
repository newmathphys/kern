# KERN v2.8.22 — `midpoint` доказан полностью (`trusted: 0`)

## Главное: пруф-чекер проверяет аксиомы Евклида для `div`/`mod`

До этого релиза эталонный пример `midpoint` (`low <= low + (high - low) / 2 <= high`) выходил
со статусом `[PROOF PARTIAL]`: 5 шагов `th-lemma arith` были «доверенными», то есть принятыми
без проверки. Причина названа измерением: в выводе Z3 стоят аксиомы целочисленного деления.

Теперь пруф-чекер проверяет их сам (`src/verifier/proof_check.zig`, правило `euclidAxiomEq`):

| Что проверяется | Условие приёма |
|:--|:--|
| тождество деления | `A = k*div(A,k) + mod(A,k)` при целом `k > 0` |
| нижняя граница остатка | `mod(A,k) >= 0` |
| верхняя граница остатка | `mod(A,k) <= k-1` |
| две переформулировки | `(not (= A RHS)) or (>= X 0)` / `(<= X 0)`, где `X` линейно равен `A - RHS` |

Звучность обеспечивается двумя проверками, а не доверием: (а) `k` — один и тот же положительный
литерал во всех вхождениях; (б) `A` внутри `div`, внутри `mod` и в равенстве — **один полином**
по каноническому ключу (сортировка слагаемых по имени), поэтому `(- high low)` и
`(+ (* (- 1) low) high)` считаются одним и тем же.

**Измерено на `examples/anatomy/law_ok.py` (`workspace` → `midpoint.smt2`):**

```
[PROOF VERIFIED] steps: 58 | premises bound: 3/4 | mp: 8 | rewrite (linear): 11 | farkas: 7 | trusted: 0 | holes: 0
```

было `trusted: 5` (а до правок сессии — `trusted: 12`).

## Двусторонний контроль (без него это была бы дыра)

- `make proof-tamper`: **35 подделок, ПРИНЯТО 0**;
- `make evm-proof-check`: `SDIV(MIN, -1) = MIN` по-прежнему доказан **без доверенных шагов** —
  канонический ключ включается только как фолбэк (для константных `div`/`mod` работает старый путь);
- подделки вида `(<= (mod A 2) 0)` и `A = 3*div(A,2) + mod(A,2)` не проходят: `0 != k-1`,
  коэффициент `3 != k`.

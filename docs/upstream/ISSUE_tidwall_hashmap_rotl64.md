# Черновик Issue: `XXH_rotl64` в `hashmap.c` — UB и переполнение в граничных значениях `r`

Адресат: https://github.com/tidwall/hashmap.c
Проверено на: `3735986` (HEAD, `--depth 1`, 2026-11-09)
Апплаенс: KERN v2.8.3 (`--xray`)

## Как найдено

Находка анализатора (дословно):

```
hashmap.c: [OVERFLOW PATH] XXH_rotl64: переполнение типа `i32` в `64 - r` — UB до возврата
```

## Код

```c
// hashmap.c:675-677
static uint64_t XXH_rotl64(uint64_t x, int r) {
    return (x << r) | (x >> (64 - r));
}
```

## Два независимых факта

### 1. Сдвиг на 64 бита при `r == 0` — неопределённое поведение

При `r = 0` выражение `x >> (64 - r)` превращается в `x >> 64`. По стандарту C сдвиг на
величину, равную или большую ширины типа, — **UB**. Живая проверка (gcc, UBSan):

```
$ gcc -fsanitize=undefined rot.c -o rot && ./rot
rot.c:4:26: runtime error: shift exponent 64 is too large for 64-bit type 'long unsigned int'
rotl64(x,0) = 0
```

### 2. Переполнение `int` в `64 - r` при `r <= 0` в крайних значениях

`r` имеет тип `int`; при `r = INT_MIN` выражение `64 - r` не представимо в `int` (signed overflow — тоже UB).
Это уже не гипотетика: `r` — параметр публичной по смыслу вспомогательной функции, домен не
ограничен ни типом, ни проверкой.

## Почему это практично

Внутри файла `XXH_rotl64` вызывается только с `r = 31`, поэтому в текущих путях исполнения
проблема не проявляется. Но функция `static` в заголовочной части алгоритма xxHash — при любом
переиспользовании (копирование блока XXH64 в другой проект, что делают постоянно) вызов с
`r = 0` даёт UB, который оптимизатор вправе превратить в произвольный код.

## Предлагаемая правка (2 строки)

```c
static uint64_t XXH_rotl64(uint64_t x, int r) {
    r &= 63;                       /* домен: 0..63 */
    return (x << r) | (x >> ((64 - r) & 63));
}
```

Либо, без ветвлений и полностью на беззнаковой арифметике:

```c
static uint64_t XXH_rotl64(uint64_t x, unsigned r) {
    r &= 63u;
    return r ? ((x << r) | (x >> (64u - r))) : x;
}
```

## Что приложить к Issue

* версия репозитория: `3735986`;
* вывод UBSan (выше, дословно);
* отметку, что в текущих вызовах (`r = 31`) проблема не воспроизводится — это защита от
  возражения «у нас так не вызывается».

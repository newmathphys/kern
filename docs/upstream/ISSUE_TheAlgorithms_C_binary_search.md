# Черновик Issue: `binary_search.c` — переполнение `r - l` при отрицательном `l`

Адресат: https://github.com/TheAlgorithms/C
Проверено на: `e5dad3f` (HEAD, `--depth 1`, 2026-11-09)
Апплаенс: KERN v2.8.3 (`--xray`)

## Код

```c
// searching/binary_search.c:21-25
int binarysearch1(const int *arr, int l, int r, int x)
{
    if (r >= l)
    {
        int mid = l + (r - l) / 2;
```

## Что не так

Форма `l + (r - l) / 2` выбрана правильно — она избегает классического `l + r`. Но она не
защищает от **отрицательного `l`**: при `l = INT_MIN` и `r > 0` выражение `r - l` выходит за
пределы `int`, что в C — undefined behaviour (signed integer overflow).

Живая проверка (gcc, UBSan) на функции, дословно вырезанной из файла:

```
$ ./bs2
bs_fn.c:5:26: runtime error: signed integer overflow: 2147483647 - -2147483648
              cannot be represented in type 'int'
```

## Почему это стоит починить

1. `l` — параметр публичной функции, ни тип, ни `assert` не запрещают `l < 0`. Репозиторий
   учебный: код копируют в свои проекты, и там `l` приходит из внешнего вызова.
2. Это ровно тот же класс, из-за которого `mid = (low + high) / 2` 20 лет ломал бинарный
   поиск в JDK (`Arrays.binarySearch`) — форма `l + (r - l) / 2` лечит половину проблемы и
   оставляет вторую.

## Предлагаемая правка

Одна строка — считать середину без промежуточного переполнения:

```c
int mid = l + (int)(((long long)r - (long long)l) / 2);
```

либо явно сузить домен и задокументировать его:

```c
assert(l >= 0 && r >= l);
int mid = l + (r - l) / 2;
```

# Модель угроз (THREAT MODEL)

> **Область:** KERN v2.5.x — ядро проверки контрактов, C-ABI, KERNFS/KIMG,
> аттестация релиза, витрина. Документ отвечает на вопрос «от чего именно
> защищает KERN и где защита кончается», а не «мы безопасны».

## 1. Активы

| Актив | Почему важен | Где живёт |
|:--|:--|:--|
| Вердикт (`T`/`F`/`N`/`B`) | решение «пропустить код» | `src/next/truth.zig`, `src/verifier/*` |
| Сертификат `.proof` | доказательство без доверия к проверяющему | `admission_gate.zig`, `proof_check.zig` |
| Аттестат релиза | связь «бинарник ↔ коммит ↔ команда сборки» | `kern.intoto.jsonl`, `.sig` |
| Ключ владельца | подпись аттестатов и `.kimg` | `~/.kern_owner_private.pem` (вне репозитория) |
| Контракты `@kern:` | спецификация, которую нельзя ослаблять | `docs/contracts.lock.json` |
| Образы `.kimg` / KERNFS | целостность данных на диске | `src/core/*` |
| Витрина и числа | доверие читателя | `README*`, `docs/index.html`, `docs/facts.json` |

## 2. Противники и что они могут

| Противник | Возможности | Что его останавливает | Остаточный риск |
|:--|:--|:--|:--|
| **ИИ-агент с правом записи** | правит код, контракты, документацию; «чинит» тесты | can-fail harness, `contracts-lock`, `metrics-guard`, `sync-check`, `ai-traces-check`, `secrets-check` | агент может ослабить `@kern:ensures`, если человек принял diff не глядя; замок это поймает **после** коммита |
| **Недоверенный вход** (файл `.kimg`, SMT-LIB, исходник на проверку) | переполнение `offset+size`, гигантский `object_count`, `../`/NUL в путях, РедОС-паттерны | checked arithmetic, лимиты, `validatePath`, таймауты, `redos.zig` | новые форматы/поля могут обойти лимиты — на каждое расширение нужен golden-vector |
| **Подмена артефакта** | подменить бинарник/аттестат/подпись | `SHA256SUMS`, Ed25519, `kid`, `attests_commit`, `tree_sha256` | подпись **своя**, не сторонний билдер: компрометация ключа владельца неотличима от легитимного релиза |
| **Скомпрометированный ключ** | выпустить «легитимный» аттестат | `kid` + публикация отпечатка + список отзыва (`INCIDENT_RESPONSE.md`) | нет прозрачного лога (Rekor) → отзыв не виден автоматически |
| **Скомпрометированный репозиторий/CI** | изменить `tools/*`, обойти гейты | гейты живут в репозитории → их можно изменить тем же коммитом | **не решается без внешнего доверенного билдера** |
| **Автор витрины (человек/агент)** | написать «работает», чего нет | `metrics-guard`, `sync-check`, `citations-check`, `codecheck`, `conformance-check` | смысловые утверждения без числа проверяются только ревью |
| **Сетевой атакующий на витрине** | XSS через данные, подмена JSON | статический сайт, данные из репозитория, без бэкенда | сторонние ссылки/шрифты — вне нашего контроля |

## 3. Границы доверия (trust boundaries)

```
[исходник] --(контракты)--> [kernc] --(SMT)--> [Z3] --(вердикт)--> [врата]
                                                    ^
                                      Z3 — ДОВЕРЕННЫЙ компонент:
                                      unsat считается доказанным
[git] --(tree_sha256)--> [make seal] --(Ed25519)--> [kernc.intoto.jsonl]
                                                    ^
                                      ключ владельца — ДОВЕРЕННЫЙ
```

| Внутри TCB | Вне TCB |
|:--|:--|
| Z3 (его `unsat`) | proof-checker (проверяет сертификаты сам, `trusted: 0`) |
| ключ владельца | пользователь, который не проверяет подпись |
| git-история (её нельзя переписать без force-push) | GitHub как хостинг |

**`trusted: 0` относится к proof-checker, а НЕ ко всей системе.** Z3 доверяется;
снять это можно только proof production (backlog).

## 4. Что KERN НЕ защищает

- **Не** доказывает отсутствие багов в чужом коде: контракт может быть неполным.
- **Не** обнаруживает злонамеренный контракт (`requires = false` ⇒ «доказано» вакуумно).
- **Не** защищает от компрометации GitHub-аккаунта владельца.
- **Не** даёт изоляции исполнения: `kernx` — VM без хостовых вызовов, но это не песочница ОС.
- **Не** гарантирует байт-идентичность сборки: локальная и CI-сборка могут отличаться путями тулчейна (см. `ATTESTATION_PASSPORT.md`).

## 5. Проверки, которые поддерживают модель

`make ci` · `make canfail` (полный контур: все проверки доказаны как «умеющие падать») · `make secrets-check` · `make verify-attestation`
· `make metrics-guard` · `make sync-check` · `make citations-check` · `make conformance-check`
· `make codecheck` (FP = 0).

Каждая новая CHECK-цель обязана уметь падать — иначе она не защита, а декорация.

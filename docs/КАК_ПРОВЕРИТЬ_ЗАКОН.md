# Как проверить закон: три команды

Закон — это два комментария над функцией. Дальше решает машина: либо доказывает, либо даёт число.

```python
# @kern:requires partial_count > max_chunks and max_chunks >= 1
# @kern:ensures  result >= 2 and result <= partial_count
def pick_fan_in(partial_count: int, max_chunks: int) -> int:
    fan = (partial_count + max_chunks - 1) // max_chunks
    return fan if fan > 2 else 2
```

## Команда 1 — вердикт

```bash
python3 tools/kern_contracts.py examples/law_demo.py
```
```
  [PASS] pick_fan_in: ДОКАЗАНО
  [FAIL] pick_fan_in_wrong_law: КОНТРАКТ НАРУШЕН
         ВЕРДИКТ  : ОПРОВЕРГНУТО (найден контрпример / sat, Белнап F)
         [КОНТРПРИМЕР] max_chunks = 1, partial_count = 3, result = 3
         [RUNTIME CONFIRMED] нарушение подтверждено и в рантайме (0% ложных срабатываний)
ИТОГО: доказано 1 | нарушено 1 | НЕ РЕШЕНО 0 | ЛОЖНЫХ ТРЕВОГ 0
```

Читается так: `ДОКАЗАНО` — контрпримера нет в пределах закона; `КОНТРПРИМЕР` — вот конкретные
числа, на которых закон ломается; `[RUNTIME CONFIRMED]` — эти числа подставлены в живую функцию.

## Команда 2 — посмотреть само уравнение

```bash
python3 tools/kern_contracts.py --emit-smt2 /tmp/demo examples/law_demo.py
cat /tmp/demo/law_demo_pick_fan_in.smt2
```
```lisp
(set-logic ALL)
(declare-const partial_count Int)
(declare-const max_chunks Int)
(declare-const result Int)
(assert (and (> partial_count max_chunks) (>= max_chunks 1)))   ; ЗАКОН: что верно на входе
(assert (= result (ite (> … ) (div (- (+ partial_count max_chunks) 1) max_chunks) …)))  ; КОД
(assert (not (and (>= result 2) (<= result partial_count))))    ; ОТРИЦАНИЕ закона
(check-sat)
```

Никакой магии: три строки — «что допустимо на входе», «что делает функция», «пусть закон нарушен».
`unsat` = таких чисел нет, `sat` = решатель их предъявит.

## Команда 3 — независимая перепроверка вывода (не верим Z3 на слово)

```bash
./zig-out/bin/kernc prove /tmp/demo/law_demo_pick_fan_in.smt2
```

## Как читать пруф-чекер — два честных случая из этой же сессии

**Случай A (полный сертификат):** `archetype-py :: _ensure_workers`
```
[PASS] ensure_workers: ДОКАЗАНО
  [PROOF VERIFIED] steps: 29 | premises bound: 3/3 | mp: 5 | rewrite (linear): 8 | trusted: 0 | holes: 0
```
`trusted: 0` и `holes: 0` — **каждый** шаг проверен. Это цель.

**Случай B (закон доказан, но вывод проверен частично):** `pick_fan_in`
```
ВЕРДИКТ  : ДОКАЗАНО (допущено)
[ПРУФ-ЧЕКЕР] шагов 94 | посылок 3/4 | mp 9 | резолюция 15 | Фаркаш 1 | rewrite(лин.) 17
[PROOF PARTIAL] … НЕ ПОДТВЕРЖДЕНО: доверенных шагов 12
```
Здесь Z3 доказал, но 12 шагов чекер структурно не проверяет (арифметика с `ite`/`div`).
Поэтому вердикт — `ДОКАЗАНО`, но **не** `[PROOF VERIFIED]`. Разница показывается, а не сглаживается.

## Что делать, чтобы выйти на `trusted: 0`

Формулировать тело и закон в линейной арифметике без ветвлений внутри выражения: сравнения,
сложение/вычитание, умножение на константу, `div`/`mod` на положительную константу. Пример —
`_ensure_workers` выше (29 шагов, `trusted: 0`). Как только в теле `ite` по переменной или
произведение двух переменных — либо `PROOF PARTIAL`, либо `SKIP` («нелинейное умножение»).

## Проверка контрпримера руками (30 секунд)

```bash
python3 -c "import math; p,m=3,1; print(max(2, math.ceil(p/m)))"   # 3
node -e "console.log(Math.max(2, Math.ceil(3/1)))"                 # 3
```
Если числа совпали с `[КОНТРПРИМЕР]` — закон действительно ложен, и это можно предъявлять.

## Чего этот способ НЕ делает

- Не ищет баги в коде без закона: `--xray` — подсказчик скрытых предусловий (см.
  `docs/ПАСПОРТ_ВОЗМОЖНОСТЕЙ.md`), его строка не является обвинением.
- Не доказывает нелинейную арифметику (`r * cols`) — честный `SKIP`.
- Не отправляет ничего наружу: заявка в чужой репозиторий — только вручную и только при
  воспроизведении публичным вызовом на нормальном входе.

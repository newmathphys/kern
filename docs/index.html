KERN

Zero-trust L0–L5 verification gateway for AI-written code — a claim is admitted only with machine evidence.

Download static binary (v2.4.0) Read the README Documentation

What it is

  • A gate, not a linter. Text is not evidence: a claim becomes e = 1 only if Z3 proves it, or if a reproducible execution record backs it.
  • Bidirectional distrust of the solver. Every UNSAT proof DAG is re-checked inside Zig (proof_check.zig), and every SAT counterexample is replayed against the contract before it is reported.
  • Polyglot contract checking. @kern:requires / @kern:ensures annotations are read from .py, .zig, .c and .rs — with machine types, so i32 overflow and division by zero are caught.

Quickstart — and verify what you downloaded

# 1. Download the static binary (musl) and VERIFY its checksum before running it
curl -fsSLO https://github.com/newmathphys/kern/releases/download/v2.4.0/kernc-x86_64-linux-musl
curl -fsSLO https://github.com/newmathphys/kern/releases/download/v2.4.0/SHA256SUMS
sha256sum -c SHA256SUMS          # supply-chain check, no trust required
chmod +x kernc-x86_64-linux-musl

# 2. Prove a contract with real Z3
./kernc-x86_64-linux-musl prove formal/example.smt2      # -> e=1 PROVEN / e=0 counterexample

# 3. From source: build, test, check contracts, run the formal proofs
git clone https://github.com/newmathphys/kern && cd kern
zig build && zig build test        # 279 core tests
make contracts                      # polyglot @kern: contracts (Python / Zig / C / Rust)
./formal/check.sh                   # Lean 4: 8 files, 42 theorems, 0 sorry

Four traps an AI agent falls into — and how KERN refuses them

  • Vacuous precondition (false ⟹ anything): a contradictory requires would make any broken body "provable" → KERN reports [VACUOUS] precondition is unsatisfiable (empty domain) and keeps the gate closed.
  • Weakening the specification: deleting a failing @kern:ensures is the cheapest cheat → every contract is fingerprinted in docs/contracts.lock.json, and any removal or edit is a hard error (rc = 2).
  • Silent behaviour change during refactoring: no contracts required → KERN checks ∃x: f_old(x) ≠ f_new(x) over all of ℤ and prints the exact input where the two versions disagree.
  • A counterexample that lives only in a log: --emit-pytest turns it into a real regression test that fails on the current code, and --sarif / --github-annotations put it on the exact line inside a pull request.

For AI agents (MCP)

Five tools are exposed over stdio for Claude Code / Cursor and any MCP client, with 14 live self-checks (make mcp-selftest): kern_verify_smt, kern_verify_python, kern_check_contracts, kern_prove_contract, kern_check_equivalence.

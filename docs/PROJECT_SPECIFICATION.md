# 1. Проблема и идея

## 1.1 Проблема

ИИ-агенты (и люди) генерируют код и утверждения быстрее, чем их можно
проверить. Возникает **эпистемический разрыв**:

| Что заявлено | Что реально |
|:--|:--|
| «Тесты проходят на 100 %» | строка `print("100% ЗАЩИТА")`, зашитая в код |
| «Проверено» | текст в README без единого прогона |
| «Код эквивалентен» | «выглядит похоже» |

Ключевое наблюдение: **зелёный результат ничего не доказывает**, потому что
проверка, которая не может упасть, тоже даёт «зелёно». За историю проекта это
подтвердилось **20 раз** (см. §15).

## 1.2 Идея

KERN — **арбитражный шлюз истины**. Утверждение получает статус «доказано»
**только при машинной опоре** одного из трёх видов:

1. **Вердикт SMT-решателя** (Z3): `unsat` для `∀`-контракта → доказано.
2. **Формальное доказательство** (Lean 4): теорема компилируется без `sorry`.
3. **Подтверждённый прогон**: команда + код возврата 0 + отсутствие вакуумности.

Всё остальное — **честный отказ `e=0`**, а не «наверное работает».

## 1.3 Три принципа

| Принцип | Формулировка |
|:--|:--|
| **Fail-closed** | Неизвестность → отказ, а не допуск. Тайм-аут ≠ доказательство |
| **Один источник вердикта** | Вердикт приходит ТОЛЬКО от внешнего доверенного чекера. Данные, которыми управляет ИИ (`witness_payload`), вердикта не формируют |
| **Доказательство не-вакуумности** | Каждая проверка обязана **уметь упасть**; это проверяется автоматически (`canfail`) |

# 2. Математическая основа

## 2.1 Решётка Белнапа B4

Состояние знания о факте описывается **двумя независимыми битами**:

| p (подтверждение) | n (опровержение) | Статус | Смысл |
|:--:|:--:|:--:|:--|
| 0 | 0 | **N** | нет свидетельств |
| 1 | 0 | **T** | подтверждено (истина) |
| 0 | 1 | **F** | опровергнуто (ложь) |
| 1 | 1 | **B** | **конфликт** (both — и за, и против) |

Кодирование (как в спецификации): `code = p | (n << 1)`.

```zig
// src/core/eq2.zig
pub const Eq2 = enum(u2) { N = 0, T = 1, F = 2, B = 3 };

pub fn encode(pos: u1, neg: u1) Eq2 {          // code = p | (n << 1)
    return @enumFromInt(@as(u2, pos) | (@as(u2, neg) << 1));
}
```

## 2.2 Операции

| Операция | Формула | Реализация | Смысл |
|:--|:--|:--|:--|
| **JOIN_K** (слияние знаний) | `(p_a ∨ p_b, n_a ∨ n_b)` | побитовое `OR` | объединить свидетельства |
| **MEET_K** (пересечение) | `(p_a ∧ p_b, n_a ∧ n_b)` | побитовое `AND` | общее знание |
| **notB** (отрицание) | `(n, p)` | сдвиг битов | инверсия |

```zig
pub fn joinKnowledge(a: Eq2, b: Eq2) Eq2 { return @enumFromInt(@intFromEnum(a) | @intFromEnum(b)); }
pub fn meetK(a: Eq2, b: Eq2) Eq2 { return @enumFromInt(@intFromEnum(a) & @intFromEnum(b)); }
```

**Почему это важно (аккумулятор вместо перезаписи).** Если у одной фичи два
теста — зелёный и красный, то `JOIN_K(T, F) = B` → **конфликт**, `e=0`.
Наивная реализация «статус = результат последнего теста» дала бы `T` (ложное
доказательство). Именно этот дефект был найден и закрыт (§15, дефект про гонку).

## 2.3 Ключевые законы (проверены Lean 4 и тестами)

| Закон | Формулировка |
|:--|:--|
| **Изоляция противоречия** | `T ⊔ F = B` — противоречие НЕ схлопывается в одно из слагаемых |
| **Коммутативность** | `a ⊔ b = b ⊔ a` |
| **Ассоциативность** | `(a ⊔ b) ⊔ c = a ⊔ (b ⊔ c)` |
| **Идемпотентность** | `a ⊔ a = a` |
| **Де Морган** | `¬(a ⊔ b) = ¬a ⊓ ¬b`, `¬(a ⊓ b) = ¬a ⊔ ¬b` |
| **Инволюция** | `¬¬a = a` |
| **Анти-вакуум** | пустое предусловие (`requires false`) НЕ даёт `T` |

## 2.4 Мастер-формула Врат

```
e(c) = 1  ⟺  (eq2_status = T)  ∧  (witness подтверждён внешним чекером)

где eq2_status формируется ТОЛЬКО из вердикта чекера:
    Proved                → T
    Counterexample        → F
    VacuousPrecondition   → N  (или PolicyViolation при анти-вакууме)
    Timeout / Unknown     → N   ← тайм-аут НЕ является доказательством
```

`e` — однобитное значение допуска: `1` = пропущено в прод, `0` = отказ.

## 2.5 Унификация человек↔ИИ (Уравнение V)

Задача: согласовать ограничение архитектора `human_max` с предложением ИИ
`ai_min`. Пересечение политопов непусто, если `ai_min ≤ human_max`.

```
Δ = ai_min ⊖ human_max          (сатурирующее вычитание)

Δ > 0  →  [B] КОНФЛИКТ,  ∇error = Δ  → отправить агенту на исправление
Δ = 0  →  [T] УНИФИКАЦИЯ УСПЕШНА
```

```zig
const delta = ai_min -| human_max;   // сатурирующее вычитание (0 при ai_min <= human_max)
```

`∇error` — **градиент ошибки**: числовая мера рассогласования, которую агент
использует как сигнал правки. Это механизм RLAIF (Reinforcement Learning from
AI Feedback) без обучения: итерация «предложил → получил ∇ → исправил» сходится,
что **доказано в Lean 4** (`KernConvergence.lean`, сильная формулировка).

# 3. Архитектура L0–L5

Проект разделён на **6 уровней**. Каждый уровень имеет свои гарантии.

| Уровень | Название | Что делает | Гарантия |
|:--:|:--|:--|:--|
| **L0** | Формат | `.kimg`: заголовок 128 б + таблица дескрипторов 96 б + payload | Безопасная арифметика, Merkle-корень, zero-copy |
| **L1** | Крипто-целостность | **BLAKE3-256** (по умолчанию; SHA-256 — по флагу) заголовка, таблицы и **содержимого** объектов | Подмена байта → `MerkleRootMismatch` / `PayloadTampered` |
| **L2** | ФС | KERNFS: пути `/raw/…`, `/claims/…` | Path-traversal, NUL-инъекция закрыты |
| **L3** | Врата Истины | Вердикт из внешнего чекера; решётка Белнапа | Обход «одним байтом» закрыт |
| **L4** | SMT/теории | Z3-мост, 5 теорий, CEGIS-синтез, UNSAT-core | `e=1` только при реальном `unsat` |
| **L5** | Доказательства | Lean 4: законы решётки, сходимость, zero-copy | 0 errors, 0 `sorry` |

Плюс **вертикальный срез KERN-Next** — язык `.kern` → SQLite-каталог →
snapshot/diff → agent packet.

```
.kern (текст)  →  parser  →  validate  →  catalog(.kdb)  →  snapshot(.ksnap)
                                                          →  agent_packet.json
                                                          →  report.md

.kern  →  kernc build  →  .kimg (бинарный образ)
                          ├─ check-integrity  (Merkle)
                          ├─ ls / cat         (KERNFS)
                          ├─ verify           (Врата + Z3)
                          ├─ run              (KERN-X)
                          ├─ handoff          (agent packet)
                          └─ report           (отчёт из образа)
```

# 4. Формат `.kimg` байт-в-байт

## 4.1 Заголовок (128 байт, `extern struct`)

| Смещение | Размер | Поле | Назначение |
|--:|--:|:--|:--|
| 0 | 8 | `magic` | `"KIMG\r\n\x1a\n"` (как у PNG — защита от текстового режима) |
| 8 | 2 | `version_major` | проверяется |
| 10 | 2 | `version_minor` | |
| 12 | 4 | `header_size` | |
| 16 | 4 | `flags` | |
| 20 | 4 | `hash_algo` | 1 = BLAKE3-256, 2 = SHA-256 (**валидируется**) |
| 24 | 8 | `block_size` | |
| 32 | 8 | `object_table_offset` | **выровнен по 8** |
| 40 | 8 | `object_table_size` | |
| 48 | 8 | `object_count` | |
| 56 | 8 | `data_payload_offset` | **выровнен по 8** |
| 64 | 32 | `root_digest` | Merkle-корень таблицы |
| 96 | 32 | `header_checksum` | SHA-256 первых 96 байт |

**Comptime-инварианты** (сборка падает, если нарушены):

```zig
comptime {
    std.debug.assert(@sizeOf(KimgHeader) == 128);
    std.debug.assert(@offsetOf(KimgHeader, "object_table_offset") == 32);
    std.debug.assert(@offsetOf(KimgHeader, "object_count") == 48);
    std.debug.assert(@offsetOf(KimgHeader, "data_payload_offset") == 56);
}
```

Это **zero-cost гарантия**: если размер структуры изменится из-за флагов
компилятора, `zig build` упадёт — бинарник физически не сможет сделать

## 4.2 Дескриптор объекта (96 байт)

| Смещение | Размер | Поле |
|--:|--:|:--|
| 0 | 32 | `digest` — SHA-256 **содержимого** объекта |
| 32 | 8 | `payload_offset` |
| 40 | 8 | `uncompressed_size` |
| 48 | 8 | `compressed_size` — **размер на диске** (см. §15, дефект #55) |
| 56 | 4 | `type_id` |
| 60 | 2 | `flags` — бит 1 = `HAS_LOGICAL_PATH`, биты 2–3 = статус Белнапа |
| 62 | 1 | `compression_codec` |
| 63 | 1 | `scope_depth` |
| 64 | 4 | `logical_path_offset` (в пул строк) |
| 68 | 4 | `schema_version` |
| 72 | 24 | **reserved — обязаны быть нулями** |

**CONF-15 (анти-стеганография):** 24 reserved-байта проверяются на ноль
**SWAR-методом** — три машинных слова `u64` объединяются побитовым `OR`:

```zig
const r0 = std.mem.readInt(u64, bytes[72..80], .little);
const r1 = std.mem.readInt(u64, bytes[80..88], .little);
const r2 = std.mem.readInt(u64, bytes[88..96], .little);
if ((r0 | r1 | r2) != 0) return KimgError.InvalidReservedBytes;
```

Одна ветвь вместо 24 итераций. Зачем: скрыть данные в «пустых» байтах —
классический приём сокрытия информации; проверка делает образ каноническим.

## 4.3 Типы объектов

| `type_id` | Тип | Что внутри |
|:--|:--|:--|
| `0x0002` | Source | исходный файл |
| `0x0005` | Claim | контракт/утверждение |
| `0x0007` | Bytecode | программа для KERN-X |
| прочие | зарезервированы | |

## 4.4 Merkle-корень

```
root = SHA256( SHA256(desc[0]) ‖ SHA256(desc[1]) ‖ … ‖ SHA256(desc[n-1]) )
```

Покрывает **таблицу дескрипторов**. Содержимое объектов покрывается
**отдельно** — через `digest` каждого дескриптора (§5.4, `PayloadTampered`).

## 4.5 Безопасная арифметика (SEC-01, offset bomb)

Все вычисления границ — через проверяемые операции:

```zig
const t_end = std.math.add(u64, h.object_table_offset, h.object_table_size)
    catch return KimgError.OutOfBoundsOffset;
const delta = std.math.mul(u64, i, 96) catch return KimgError.OutOfBoundsOffset;
```

**Зачем:** образ — недоверенный вход. `i * 96` при `i = 1e9` переполняет `u64`
и даёт маленькое число → чтение по ложному смещению. Проверяемые операции это
исключают, плюс добавлена граница `object_count ≤ table_size / 96`.

## 4.6 Детерминизм и атомарность

- **Детерминизм сборки:** одинаковый вход → побайтово одинаковый образ
  (проверяется в `src/sim_test.zig`, VOPR-стиль как у TigerBeetle).
- **Атомарная запись (crash-consistency):** запись во временный файл →
  `rename` → `fdatasync` **каталога**. При аварии (SIGKILL, отключение
  питания) образ либо стар, либо нов — но **никогда не промежуточный**.

# 5. KERNFS — маршрутизатор

## 5.1 Пространства имён

| Путь | Что возвращает |
|:--|:--|
| `/raw/<путь>` | содержимое исходного объекта (тип `0x0002`) |
| `/claims/<id>/status` | `N` / `T` / `F` / `B` (из битов 2–3 флагов) |
| `/claims/<id>/contract` | текст контракта |
| `/claims/<id>/e_value` | `0` или `1` |

## 5.2 Безопасность путей

```zig
pub fn validatePath(path: []const u8) !void
```

| Атака | Как закрыта |
|:--|:--|
| Path traversal | запрет `..`, `.`, `//`, требуется ведущий `/` |
| NUL-инъекция | запрет байта `0x00` (обрыв C-строки) |
| Побег через `/claims` | строгая проверка префикса |

## 5.3 Двойной путь чтения

| Функция | Проверяет SHA-256? | Для чего |
|:--|:--:|:--|
| `objectPayload` / `payloadSlice` | **да** | пользовательское чтение (`cat`, `read`) |
| `objectPayloadRaw` | нет | замеры производительности, внутренние пути |

**Единое правило размера (дефект #55):** читатель берёт **`compressed_size`**
(размер на диске) независимо от кодека. Раньше две функции выбирали размер
**противоположно** — и при `compressed_size ≠ uncompressed_size` вернули бы
разные срезы. Дефект был невидим, потому что писатель ставит оба поля равными.

## 5.4 Защита целостности содержимого

Merkle-корень покрывает **только таблицу**. Поэтому подмена байта в payload
иначе прошла бы незамеченной:

```zig
var got: [32]u8 = undefined;
std.crypto.hash.sha2.Sha256.hash(sl, &got, .{});
if (!std.mem.eql(u8, &got, &obj.digest)) return KernFsError.PayloadTampered;
```

Это был **реальный дефект**, найденный тестом: `PASSWORD=12345 → 92345`
читалось без ошибки. Теперь — `PayloadTampered`.

## 5.5 Запись запрещена

```zig
pub fn write(_: *KernFS, _: []const u8, _: []const u8) KernFsError!void {
    return KernFsError.AccessDenied;   // CONF-06: образ только для чтения
}
```

Иммутабельность образа — часть модели безопасности: доказанный артефакт
нельзя изменить «на месте».

# 6. Врата Истины

**Файл:** `src/verifier/admission_gate.zig` (323 строки) — сердце проекта.

## 6.1 Сертификат доказательства (PC3)

```zig
pub const ProofCertificate = struct {
    target_ast_digest: [32]u8,     // хэш кода, который проверяем
    contract_digest:   [32]u8,     // хэш контракта (Pre/Post)
    checker_id:        u32,        // 0x01 = Z3 SMT, 0x02 = Lean 4
    witness_payload:   []const u8, // «терм доказательства» — ДАННЫЕ ИИ
};
```

**Инвариант безопасности:** вердикт **не выводится** из `witness_payload`.
`witness_payload` — это вход для чекера, а не источник истины.

## 6.2 Доверенный чекер

```zig
pub const CheckerVerdict = enum {
    Proved,                 // доказано
    Counterexample,         // найден контрпример
    VacuousPrecondition,    // предусловие невыполнимо (вакуум!)
    Timeout,                // тайм-аут решателя
    Unknown,                // решатель не смог
};
```

**Единственный источник вердикта.** Функция `runTrustedChecker` **удалена**:
она читала вердикт из байта `payload[0]` — то есть из данных, которыми
управляет ИИ. Байт `0xAA` давал `e=1`. Это была **АТАКА 1** из аудита;
закрыта тестом «ФИКС АТАКИ 1: ОДИН БАЙТ 0xAA больше НЕ даёт e=1».

## 6.3 Политика верификации

```zig
pub fn allows(self: VerificationPolicy, checker_id: u32) bool {
    if (checker_id >= 32) return false;   // fail-closed
    const mask = @as(u32, 1) << @as(u5, @intCast(checker_id));
    return (self.allowed_checkers & mask) != 0;
}
```

⚠️ **Ловушка, найденная аудитом:** маска считается как `1 << checker_id`,
поэтому `allowed_checkers = 1` разрешает `checker_id = 0`, **а не 1**.
Чтобы разрешить чекер 1, нужно `allowed_checkers = 2`.

🔴 **Исправленный дефект:** раньше стояло `@truncate(checker_id)` (u32 → u5).
Для `checker_id ≥ 32` индекс **заворачивался**: 32 → 0, 64 → 0, …
То есть «чекер 32» получал права чекера 0. Теперь всё вне диапазона
**отвергается** (fail-closed).

## 6.4 Основная логика

```zig
switch (checker.run(...)) {
    .Proved => { eq2 = .T; e_val = 1; },          // GATE OPEN
    .Counterexample => { eq2 = .F; },             // опровергнуто
    .VacuousPrecondition => {
        if (policy.require_anti_vacuity)
            return GateError.PolicyViolation;      // CONF-04
        eq2 = .N;
    },
    .Timeout, .Unknown => { eq2 = .N; },          // тайм-аут НЕ доказательство
}
```

## 6.5 Аккумулятор Белнапа (не перезапись!)

Когда у одного утверждения **несколько** свидетельств исполнения, статус
накапливается через `JOIN_K`, а не перезаписывается последним:

```
тест зелёный (T) ⊔ тест красный (F) = B (КОНФЛИКТ) → e = 0
```

**Наивная реализация** («статус = результат последнего теста») дала бы `T` —
ложное доказательство при живом красном тесте. Реализация —
`src/next/truth.zig`, `Bit.join` + `status()`.

## 6.6 Анти-вакуумность

**Вакуумное доказательство** — контракт с невыполнимым предусловием
(`requires false`): формально доказан, но не значит ничего.
KERN отвергает его при `require_anti_vacuity = true`.

Пример: контракт `assert(x > 5 ∧ x < 2)` → предусловие невыполнимо →
`VacuousPrecondition`, а **не** «доказано».

# 8. KERN-X — VM с топливом

**Файл:** `src/runtime/kern_x.zig`.

## 8.1 Набор инструкций

| Код | Инструкция | Действие |
|:--:|:--|:--|
| `0x00` | `NOP` | ничего |
| `0x02` | `PUSH imm8` | положить байт на стек |
| `0x03` | `STORE` | `memory[addr] = value` (со стека) |
| `0x04` | `LOAD` | положить `memory[addr]` на стек |
| `0x05` | `ADD` | сложить два верхних |
| `0xFF` | `HALT` | успешное завершение |

## 8.2 Модель топлива (fuel)

```
fuel = N
каждый шаг: fuel -= 1
fuel == 0  →  OutOfFuel (контролируемый отказ)
```

**Зачем:** это **ограниченная проверка модели** (BMC-принцип). Зависание
физически невозможно: 10 000 `NOP` с `fuel = 100` → `OutOfFuel`, не
бесконечный цикл. Тот же приём защищает от «зависающих» багов QuixBugs.

## 8.3 Границы

| Проверка | Ошибка |
|:--|:--|
| Выход за память | `STORE`/`LOAD` отвергаются |
| Неизвестный опкод | `InvalidOpcode` |
| Исчерпание топлива | `OutOfFuel` |

Все три — **контролируемые** (не паника), что проверено тестами.

## 9.2 Статусная система (§7)

```
proven · refuted · verified · tested · compiled · empirical
hypothesis · blocked · unknown · not_found · not_yet_reproducible
conflicted   ← расширение: КОНФЛИКТ (Белнап B)
```

`conflicted` — **расширение словаря спецификации**, необходимое для
аккумулятора `joinK`: без него конфликт двух свидетельств невыразим.

## 9.3 Валидатор: 10 правил

| Код | Уровень | Проверка |
|:--|:--|:--|
| `V001` | warning | неизвестный вид артефакта |
| `V002` | err | пустой путь / пустое утверждение / нет имени проекта |
| `V004` | warning | ссылка на неразрешённое свидетельство |
| `V005` | err | **дубликат ID** |
| `V007` | err | неверный формат хэша (ожидается `algo:hex64`) |
| `V008` | err | метрика без имени или `NaN` |
| `V010` | warning | `blocked`/`unknown` без явной пометки `context` |

## 9.4 Резолюция `N → T / F / B`

Главный механизм «оживления» заявлений:

```
README: «✅ проверено»  →  Claim (empirical, N)
                              ↓  Execution Runner: запуск теста
                        exit_code = 0  →  Bit{T}
                        exit_code ≠ 0  →  Bit{F}
                              ↓  аккумулятор (НЕ перезапись)
                        join(T, F) = B  →  conflicted
```

```zig
pub fn status(self: Bit) ?ast.Status {
    if (self.p and !self.n) return .tested;     // T
    if (!self.p and self.n) return .refuted;    // F
    if (self.p and self.n) return .conflicted;  // B
    return null;                                // N — нет свидетельств
}
```

| **Крипто-отпечатки** | SHA-256 обоих потоков → в свидетельство |
| **Анти-вакуум** | AST-проверка: тест без единого `assert` → не даёт `T` |
| **Маскирование секретов** | API-ключи/JWT/Bearer/`sk-` вычищаются **до** хэширования |
| **Авто-дискавери** | сам находит `test_*.py` и цель `test:` в Makefile |

# 11. Контур доверия: canfail, CI, реестр

**Это то, что отличает KERN от «просто верификатора».** Он проверяет
**самого себя**.

## 11.1 Проблема, которую решает canfail

Зелёный CI **ничего не доказывает**: проверка, которая не может упасть,
тоже возвращает `RC=0`. За историю проекта это подтвердилось **20 раз** (§15).

```
    3. ожидаем НЕНУЛЕВОЙ код возврата
         покраснела   → проверка РАБОТАЕТ      [PASS]
         осталась зелёной → ВАКУУМНАЯ           [FAIL]
    4. гарантированный откат дерева
```

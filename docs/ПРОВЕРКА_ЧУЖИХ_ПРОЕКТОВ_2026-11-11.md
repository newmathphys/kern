# Проверка чужих проектов из ветки r/opensource «Contributors wanted» (2026-11-11)

**Правило, по которому это делалось:** ничего не публикуем и не открываем заявок. Проверка идёт
локально, код скачивается в `/tmp` (не в `~/.cache` — диск бережём), и любой «дефект» обязан
подтвердиться **живым компилятором/рантаймом**, иначе он остаётся подсказкой.

## Метод

```bash
curl -sSL -o p.tgz https://codeload.github.com/<owner>/<repo>/tar.gz/HEAD
tar xzf p.tgz -C /tmp/p_<repo> --strip-components=1
KERN_DOMAIN_CLAMP=0:1000 python3 tools/kern_contracts.py --xray /tmp/p_<repo>
# далее ЛЮБАЯ находка проверяется: rustc / python3 / node / gcc -fsanitize
```

`KERN_DOMAIN_CLAMP=0:1000` сужает поиск контрпримеров до рабочего домена и **печатает** это
(одна строка на прогон), чтобы «находок 0» нельзя было прочитать как «код чист».

## Две ложные тревоги — **в моём инструменте**, а не в их коде

### 1. Делитель внутри пустого диапазона (`pencil-puzzles`, 11 × `CRASH PATH`)

Инструмент предупредил: `crates/core/src/grid.rs: neighbours: возможно деление на ноль: cols == 0`.
Код:

```rust
pub fn neighbours(rows: usize, cols: usize) -> Vec<Vec<usize>> {
    (0..rows * cols).map(|i| { let (r, c) = (i / cols, i % cols); /* … */ })
}
```

При `cols == 0` выражение `rows * cols` равно нулю, диапазон **пуст**, и тело замыкания не
выполняется ни разу. Проверено живым `rustc`:

```
cols=0 -> []
cols=2 -> [[0, 0], [0, 1], [1, 0], [1, 1]]
exit=0
```

**Вердикт: тревога ложная.** Класс дефекта инструмента: делитель, взятый из границы цикла,
диапазон которого пуст при нулевом делителе. Автору писать нечего — у него корректно.

### 2. Деление на ноль в JavaScript — не крах (`apogee`, 1 × `CRASH PATH`)

```
lib/summarize/mapReduce.js: pickFanIn: возможно деление на ноль: maxChunks == 0
```

В JS `1/0 === Infinity` (проверено `node`), исключения не будет. Плюс в самом коде есть контракт
в комментарии: «Caller guarantees partialCount > maxChunks». То есть это скрытое предусловие,
а не падение.

**Вердикт: тревога ложная** (класс «семантика деления зависит от языка»). Автору — в лучшем
случае заметка «предусловие стоит проверить в рантайме», не более.

## Что говорит это о самом KERN

Оба случая — реальные дефекты классификатора `--xray`, и они записаны, а не замазаны:

1. деление на границу **пустого** диапазона не может выполниться — нужен анализ достижимости
   тела цикла до того, как объявлять `[CRASH PATH]`;
2. в JS/Python деление на ноль не «краш» — `Infinity`/`ZeroDivisionError` это разные вещи,
   и класс должен называться по языку.

Пока это не исправлено, правило остаётся прежним: **`--xray` без закона — подсказчик**, и ни одна
его строка не идёт ни в отчёт мейнтейнеру, ни в Issue.

## Законы на ИХ функции (это и есть то, ради чего KERN существует)

Файл: `examples/oss_laws.py`. Функции переписаны из реальных репозиториев (арифметика сохранена),
рядом лежат законы `@kern:requires` / `@kern:ensures`.

### `apogee :: pickFanIn` (JS, MIT)

Исходник: `Math.max(2, Math.ceil(partialCount / maxChunks))`, в комментарии контракт
«Caller guarantees partialCount > maxChunks».

| Закон | Вердикт |
|:--|:--|
| `requires p > m and m >= 1` ⇒ `ensures 2 <= result <= p` | **ДОКАЗАНО** |
| `requires p > m and m >= 1` ⇒ `ensures result <= m` (заведомо сильный) | **ОПРОВЕРГНУТО**: `m = 1, p = 3, result = 3` |

Контрпример проверен независимо, в их собственном рантайме:

```
python3: pickFanIn(3,1) = 3 > max_chunks = 1   -> нарушено: True
node   : f(3,1) = 3        f(3,2) = 2
```

Смысл для автора: верхняя граница `result <= partial_count` выполняется **всегда** в заявленном
домене (это доказано), а вот `result <= maxChunks` — **не выполняется**, и вот вход: `(3, 1)`.
Никаких «возможно», ровно одно число.

### `pencil-puzzles :: индекс ячейки` (Rust, MIT)

Закон `r < rows ∧ c < cols ⇒ 0 <= r*cols + c < rows*cols` — **SKIP: нелинейное умножение**.
Честная причина: контрактный путь решает линейную арифметику (`QF_LIA`), произведение двух
переменных вне подмножества. Это ограничение инструмента, и оно названо, а не спрятано.

### `archetype-py :: сумма нарушений` (Python, MIT)

`ensures result >= a and result >= b` при `a, b >= 0` — **ДОКАЗАНО** (тривиально, но это проверка
пути, а не демонстрация).

### Вывод, который нельзя обойти

На **их** коде KERN дал: одно доказательство, один точный контрпример с подтверждением в их
рантайме и одно честное «вне подмножества». Это и есть разница между «0 находок» сканера
и работой верификатора: закон + ответ, который проверяем.


### `archetype-py :: _ensure_workers` (Python, MIT)

Источник: `archetype/config.py:57` — на `raw < 1` бросает `ValueError`, на верном входе
возвращает значение. Внутри закона (`raw >= 1`) ветка исключения недостижима, транскрипция faithful.

```
[PASS] ensure_workers: ДОКАЗАНО
       [PROOF VERIFIED] steps: 29 | premises bound: 3/3 | mp: 5 | rewrite (linear): 8 | trusted: 0 | holes: 0
[FAIL] ensure_workers_floor_100: КОНТРАКТ НАРУШЕН
       [КОНТРПРИМЕР] raw = 1, result = 1
       [RUNTIME CONFIRMED]
```

То есть: «валидатор не искажает значение и сохраняет нижнюю границу» — **доказано полностью**
(все 29 шагов проверены, `trusted: 0`), а «валидатор поднимает значение до 100» — **опровергнуто**
на `raw = 1`. Второй закон я придумал сам, чтобы контроль был двусторонним: без него
`ДОКАЗАНО` ничего не доказывало бы.

### `archetype-py :: new_violations` (Python, MIT) — второй полный сертификат

Источник: `archetype/check.py:183` — `ViolationCounts(total=total, new=total - suppressed, …)`.

```
[PASS] new_violations: ДОКАЗАНО
       [PROOF VERIFIED] steps: 53 | premises bound: 3/3 | mp: 10 | rewrite (linear): 15 | trusted: 0 | holes: 0
[FAIL] new_violations_always_positive: КОНТРАКТ НАРУШЕН
       [КОНТРПРИМЕР] suppressed = 0, result = 0, total = 0
```

Смысл для автора: «новых = все минус прощённые» и «новых не может быть отрицательно» — **доказано
полностью** (53 шага проверены, `trusted: 0`). А утверждение «новых всегда больше нуля» — **ложно**,
и вот вход: `total = 0, suppressed = 0`. Проверено в Python:

```
new = 0 | закон result>0: False        (total=0, suppressed=0)
new = 3 | инвариант result+suppressed==total: True   (total=5, suppressed=2)
```

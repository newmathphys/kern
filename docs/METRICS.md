## 12. Эшелоны финального штурма (1–4) — 2026-10-11

### Эшелон 1. Строгое выравнивание памяти и endianness

| Проверка | Результат |
|:--|:--|
| `KimgHeader` — ровно 128 байт, alignment 8 (comptime) | ✅ |
| Записи таблицы читаются как `[96]u8` (alignment = 1) | ✅ |

### Эшелон 4. Семантический разрыв Lean vs Zig
Файл: `formal/KernSemanticGap.lean` (8 теорем, 0 `sorry`). Команда: `make semantic-gap`.

| Теорема | Смысл |
|:--|:--|
| `unbounded_succ_gt` | в ℤ: `x + 1 > x` для любого x |
| `int32_gap` | **∃ x в i32, где `x + 1` выходит за домен** (x = 2147483647) |
| `no_blanket_transfer` | свойство ℤ **нельзя** перенести на i32 «оптом» |
| `spec_must_bound` | контракт обязан ограничивать вход доменом |
| `guarded_add_stays_in32` | guard по границе **сохраняет** домен (= `std.math.add`) |
| `int32_gap_lower` | тот же разрыв на нижней границе (вычитание) |
| `safe_inside_only` | перенос безопасен строго внутри домена |
| `boundary_requires_guard` | границы требуют явной обработки |

**Вывод:** семантический разрыв **формально доказан**; защитное правило KERN
(guard по границе) доказано корректным. Доказательство в ℤ недействительно для
i32 без явной границы — это и есть защита от ложного «ДОКАЗАНО».

### 14.1 Реальный перехват SIGBUS/SIGSEGV (`src/core/sigbus_guard.zig`)

ЗАКРЫТО «узкое место»: раньше обработчик сигнала лишь ставил флаг, а **возврат
из обработчика повторяет сбойную инструкцию** → бесконечный цикл. Теперь
используется `siglongjmp` — прыжок назад к точке `setJump()`.

> ⚠️ Находка: в glibc `sigsetjmp` — **макрос**, реальный символ `__sigsetjmp`
> (компоновка падала с `undefined symbol: sigsetjmp`).

Цель сборки отдельная (нужен libc): `make test-fault` → `src/fault_root.zig`.

### 15.2 MBPP+ (официальный EvalPlus, 378 задач)

Генерация через API (`nvidia/nemotron-3-super-120b-a12b`), оценка официальным

**Найдены ДВА дефекта инфраструктуры (оба исправлены):**

1. **Пустые сэмплы.** Часть запросов к API падает (rate-limit/таймаут) и

### 16.7 Независимая проверка вывода решателя (`src/verifier/proof_check.zig`)

|:--|:--|
| Вывод получен и структурно корректен (реальный Z3) | ✅ `confirmed = true` |

| Битый вывод распознаётся (баланс скобок) | ✅ |

> ⚠️ ЧЕСТНО: это **не** полный Alethe/LFSC-чекер (каждый шаг дедукции не
> перепроверяется аксиоматически). Это структурный контроль + проверка

### 18.2 Constant-time на уровне АССЕМБЛЕРА

Доказать constant-time на исходнике недостаточно: компилятор вправе вернуть
ранний выход (векторизация, инлайн). Анализируем **сгенерированный ассемблер**
(`tools/binlevel_verify.py`, taint-анализ линейного потока инструкций):

```
  [kern_ct_equal] (constant-time): инструкций 146, ветвлений от ДАННЫХ: 0
  [kern_early_exit_equal] (ранний выход): инструкций 41, ветвлений от ДАННЫХ: 1
      строка 21: jne	.LBB3_5
  [OK] constant-time: НЕТ ветвлений от данных
  [OK] контрольный ранний выход ОБНАРУЖЕН (проверка не пустая)
```

**Метод:** источник taint — загрузка из памяти; taint распространяется через
`mov`/логические операции; `xor r,r` снимает; если `cmp`/`test` использует
tainted-регистр или операнд-память, а следом идёт условный переход — УТЕЧКА.
Контрольный пример (ранний выход) **обязан** дать ≥1 — доказывает, что
проверка не пустая.

> Найденные при разработке анализатора ошибки (исправлены): Intel-синтаксис
> (`dst, src`), адресация в **квадратных** скобках, `setcc`/`mov` не пишут
> флаги, директивы `.loc` между `cmp` и `jcc`.

## 12. Эшелоны финального штурма (1–4) — 2026-10-11

### Эшелон 1. Строгое выравнивание памяти и endianness
Файл: `src/tests/alignment_stress.zig` (8 тестов). Команда: `make align`.

| Проверка | Результат |
|:--|:--|
| `KimgHeader` — ровно 128 байт, alignment 8 (comptime) | ✅ |
| Записи таблицы читаются как `[96]u8` (alignment = 1) | ✅ |
| `ObjectEntry` — логическая структура (72 байта), НЕ раскладка диска | ✅ |
| Разбор при смещениях 0..7 — одинаковый результат | ✅ |
| Записи таблицы читаются при смещениях 1,2,3,5,7 (невыровненно) | ✅ |
| Невыровненная таблица НЕ ломает Merkle | ✅ |
| Многобайтные поля читаются Little-Endian | ✅ |
| `isStrictlyAligned` различает выровненные и нет | ✅ |

**Вывод:** zero-copy не полагается на `@ptrCast` к выровненным структурам —
записи читаются побайтово по смещениям (`[96]u8`, alignment 1). На ARM64/RISC-V
это исключает аппаратный `Bus Error`. Раскладка зафиксирована comptime-проверками.

### Эшелон 2. Лавинный штурм хэш-таблицы (Hash Flooding)

### Эшелон 4. Семантический разрыв Lean vs Zig
Файл: `formal/KernSemanticGap.lean` (8 теорем, 0 `sorry`). Команда: `make semantic-gap`.

| Теорема | Смысл |
|:--|:--|
| `unbounded_succ_gt` | в ℤ: `x + 1 > x` для любого x |
| `int32_gap` | **∃ x в i32, где `x + 1` выходит за домен** (x = 2147483647) |
| `no_blanket_transfer` | свойство ℤ **нельзя** перенести на i32 «оптом» |
| `spec_must_bound` | контракт обязан ограничивать вход доменом |
| `guarded_add_stays_in32` | guard по границе **сохраняет** домен (= `std.math.add`) |
| `int32_gap_lower` | тот же разрыв на нижней границе (вычитание) |
| `safe_inside_only` | перенос безопасен строго внутри домена |
| `boundary_requires_guard` | границы требуют явной обработки |

**Вывод:** семантический разрыв **формально доказан**; защитное правило KERN
(guard по границе) доказано корректным. Доказательство в ℤ недействительно для
i32 без явной границы — это и есть защита от ложного «ДОКАЗАНО».

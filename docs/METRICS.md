### ⚠️ ИСПРАВЛЕНО: «51 ГБ/с» относилось ТОЛЬКО к RAW-адресации

**Что было не так.** В отчётах фигурировало «zero-copy чтение 30–51 ГБ/с» как
скорость чтения данных. Фактически это была скорость **чистой адресации
среза** (`objectPayloadRaw` — арифметика указателя без обращения к содержимому).
Реальное **безопасное** чтение (`objectPayload`) сверяет `SHA-256(payload)` с
digest дескриптора (ФИКС безопасности: Merkle покрывает только таблицу, и без
этой сверки подмена содержимого файла проходила незамеченной).

**Измерено (`src/perf_bench.zig`, ReleaseFast, 10 000 объектов / 2 МБ payload):**

| Путь чтения | Скорость | Во сколько раз медленнее |
|:--|--:|--:|
| RAW (адресация без проверки) | **76 008 МБ/с** (≈ 76 ГБ/с) | 1× |
| Безопасное (+ SHA-256) | **231 МБ/с** | **330×** |

SHA-256 на этом CPU даёт ~1.5 ГБ/с, поэтому именно хеш определяет скорость
безопасного чтения, а не «скорость памяти».

**Вывод (честно):** «скорость памяти» достижима только для адресации.
Безопасное чтение с проверкой целостности — **сотни МБ/с**, и это осознанный
компромисс: безопасность важнее пиковой цифры.

**Направление оптимизации (не реализовано):** включить payload в Merkle-дерево
(вместо отдельного digest в дескрипторе) — тогда однократная сверка корня при
монтировании валидирует ВСЁ содержимое, и чтение снова становится бесплатным.
Это изменение формата `.kimg` (v2).

### 22.2 ОС-стресс (`make os-stress`, `make flood`)

| Тест | Что проверяет | Результат |
|:--|:--|:--|
| Pipe bloat | вывод > 64 КБ (буфер пайпа) | **deadlock НЕТ** (read до wait) |
| Гигантский вывод | > лимита 4 МБ | аккуратный отказ, не паника |
| Флуд spawn | 12 потоков × 8 запросов | 0 паник, **0 утечек FD** |
| Инъекция сбоев 5 % | pipe/spawn/read падают | все учтены, FD не утекли |
| **Сигнальный флуд** | SIGTERM/SIGINT/SIGHUP 1–10 мс | **1441 запуск, 0 паник** |

**Найдено и исправлено:** в `z3_bridge` оставалось **ТРИ** вызова `child.kill()`
в путях отказа записи/чтения — **та же гонка ECHILD**, что падала на SMT-LIB.
Заменены на `std.posix.kill(pid, SIG.TERM)`.

**Почему своя инъекция сбоев, а не LD_PRELOAD/strace:** `kernc` — **статический**
бинарник (LD_PRELOAD не перехватывает), `strace` в окружении нет. Сбои
моделируются внутри моста (`fault_pct`).

### 22.3 Честная оговорка о методике

В первом прогоне `os_signal_flood.py` **ложно** счёл паниками 45 кодов
возврата: код `128+N` означает «убит сигналом N», а сигналы слали мы сами.
Исправлено: паника = SIGABRT(134)/SIGSEGV(139) или текст `panic`.
Итог после исправления: **0 реальных паник**.

«Зомби» в выводе — `python <defunct>` от **самого харнесса**, не от KERN.

### Эшелон 2. Лавинный штурм хэш-таблицы (Hash Flooding)
Файл: `tools/cache_avalanche_bench.py` (100 000 формул, каждая отличается на 1 бит).

| Метрика | SHA-256 (KERN) | Наивный (сумма байт) |
|:--|:--:|:--:|
| Лавинный эффект | **50.0%** (норма 45–55%) | 3.1% 🔴 |
| Уникальных ключей | **100 000 / 100 000** | 136 / 100 000 |
| Коллизий ключей | **0** | 99 864 |
| Занятых бакетов | **63 286 / 100 000** | 1 |
| МАКС. длина цепочки | **7** (критерий ≤ 8) | **100 000** 🔴 |
| χ² (равномерность) | 99 952 (ожид. ~100 000) | 9 999 900 000 |

### 15.2 MBPP+ (официальный EvalPlus, 378 задач)

Генерация через внешний API, оценка официальным
`evalplus.evaluate --dataset mbpp`. Результат — см. ниже.

**Найдены ДВА дефекта инфраструктуры (оба исправлены):**

1. **Пустые сэмплы.** Часть запросов к API падает (rate-limit/таймаут) и

выглядела как «провал модели», а на деле был дефект инструмента**.

## 19. Построчный аудит всего кода — 2026-10-11

Прогон по всем 63 файлам `src/` с поиском классов дефектов: тихие отказы,

долговечность записи, заворот индексов.

### 19.1 🔴 УЯЗВИМОСТЬ ВРАТ: заворот маски `checker_id`

`VerificationPolicy.allows()` использовал `@truncate(checker_id)` (u32 → u5).
Для `checker_id ≥ 32` индекс **заворачивался**: 32 → 0, 64 → 0, …
То есть недоверенный чекер 32 получал **права чекера 0**. Если политика
разрешала checker 0 — «checker 32» проходил Врата Истины.
**Исправлено:** вне диапазона 0..31 — всегда отказ (fail-closed).

### 19.2 🔴 DoS: огромное КОНЕЧНОЕ значение `exit_code`

`isFinite(m.value)` не защищает от больших конечных чисел: `metric exit_code =
999999999999999999999999999999999999` (=1e36) → `@intFromFloat(i64, 1e36)`
**паника** → инструмент падал от битого `.kern`.
**Исправлено:** проверка диапазона i64; вне диапазона свидетельство
игнорируется + предупреждение.

### 19.3 🔴 SQL-инъекция в каталоге (7 мест)

`version`, `root`, `evidence.kind`, `diagnostics.code`, `snapshots.id`,
`cache_entries.content_hash`, `countClaimsByStatus(status)` подставлялись в SQL
**без экранирования** (в отличие от `id`/`statement`).
**Исправлено:** экранирование всех значений + **белый список** имён таблиц
(имя таблицы кавычками не экранируется — это идентификатор).

### 19.4 🔴 Утечки памяти (3 места)

| Место | Что текло |
|:--|:--|
| `snapshot.readFile` | буфер до 16 МБ: строки — срезы внутрь, а буфер не отдавался |
| `cache.load` | буфер до 16 МБ + у `Cache` не было `deinit` (дубликаты строк) |
| `diffSnapshots` | возвращал срезы в снапшоты → висячие указатели после `deinit` |

Арена в CLI **маскировала** все три. **Исправлено:** `Snapshot` владеет
буфером, `Diff` копирует строки, добавлены `deinit`, тесты с `testing.allocator`.

### 19.5 🔴 Гонка: single-flight кэша был ГЛОБАЛЬНЫМ

Один мьютекс на весь кэш лечил «пчелиный рой», но **сериализовал работу над
разными формулами**: при 8 ядрах решатель вызывался из одного потока за раз.

`kimg_writer` писал tmp → rename, но **без fsync**. После отключения питания
`rename` мог обогнать запись → на диске **пустой** файл.
**Исправлено:** `fsync` файла + `fsync` каталога. То же — для `packet`,

из которых **2 — ложные**: сканер считал ЛЮБОЕ вхождение `TODO|FIXME|XXX`,
включая **свои собственные regex-шаблоны** и упоминания в прозе
(`«статус blocked: 1 (TODO)»`). После исправления остался **1 настоящий**:

```
claim:open TODOs in evalplus_results/…: 1   [blocked]
  → HumanEval/26: модель сгенерировала заглушку «# TODO: Implement me»
```

Это **подлинное свидетельство отказа LLM**, зафиксированное бенчмарком.

**Вывод:** самоаудит показал и силу (находит реальные незавершённости), и
предел (заявления документации не доказуемы без контрактов/исполнения) — и
вскрыл собственный баг ложных срабатываний.

### 20.10 АРХИТЕКТУРНЫЙ МОСТ «текст → контракт» (`make bridge`)

**Проблема:** заявления в README/спецификации — это ТЕКСТ, поэтому Врата дают
`e=0`. Учить KERN «понимать текст» нельзя: строгий верификатор превратился бы
в ненадёжную языковую модель.

**Решение:** рядом с фразой ставится **машинный якорь**:

```html
<!-- @kern:spec path="formal/gate_mask.smt2" -->
Врата: checker_id >= 32 не получает прав checker 0
```

Конвейер:

```
Markdown с якорем
   │ scan_to_kern.py  → claim { context "<путь к .smt2>" } + artifact
   ▼
.kern → kernc build → .kimg (контракт лежит в образе)
   │ kernc verify: находит контракт, прогоняет через Z3
   ▼
UNSAT → e=1 (T) ДОКАЗАНО   |   SAT → e=0 (F) КОНТРПРИМЕР
```

**Результат прогона (`make bridge`):**

```
claim `Врата: checker_id >= 32 не получает прав checker 0`: заявленный статус = N
  контракт `formal/gate_mask.smt2`: UNSAT -> e=1 (T) ДОКАЗАНО
claim `HumanEval+ зафиксирован официальным харнессом`: заявленный статус = N
  свидетельство `docs/evidence/kern-gold.kern_gold.json`: это ФАКТ исполнения, а не контракт SMT
[i] ИТОГ: доказано 1, контрпримеров 0, без контракта 16
```

**Два класса утверждений (не смешиваются):**

| Класс | Якорь | Чем подтверждается | Статус |
|:--|:--|:--|:--|
| Математическое свойство | `@kern:spec` → `.smt2` | вердикт Z3 (`unsat`) | **`e=1`** |
| Факт исполнения | `@kern:evidence` → лог | лог запуска + хэш | `admitted` |
| Просто текст | (нет) | ничем | `e=0` |

**Контроль качества контракта:** проверено, что контракт не «пустой»:
с guard (`bvult c 32`) → **unsat**; без guard → **sat** (контрпример
`cid = 32` находится). То есть контракт различает исправленную и багованую
логику, а не просто всегда даёт `unsat`.

**Найдены и исправлены 2 дефекта моста на первом же прогоне:**
1. Якорь, показанный **внутри блока кода** (```), считался настоящей
   аннотацией → документация о мосте создавала ложное утверждение.
   Фикс: якоря внутри code-fence игнорируются.
2. Docstring **самого сканера** содержит пример якоря → ложный блокер
   `anchor broken`. Фикс: собственный файл исключён.

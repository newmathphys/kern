# Как пользоваться KERN

Это памятка для человека, который пишет код (сам или с ИИ) и хочет знать:
**где его программа сломается и не сломал ли ИИ то, что работало.**

Внутри KERN около двухсот собственных проверок — они нужны, чтобы не врал сам инструмент.
Вам они не нужны. Вам нужен **один файл** `kerna` (в архиве `kerna-dist`) и **четыре команды**.

---

## Что KERN делает, если совсем коротко

Обычные тесты проверяют 2–3 числа, которые вы придумали. KERN переводит функцию в
уравнение и проверяет **весь диапазон значений сразу** — и, если находит проблему,
печатает **точные числа**, при которых всё ломается.

Три вещи, которые обычные тесты не видят:

1. **Редкое число.** Тест проверяет `5` и `10`, а при `0` — деление на ноль.
   KERN пишет: `count == 0`.
2. **Тихо изменённая логика.** ИИ переписал функцию «побыстрее», на обычных числах ответ
   тот же, а на редком — другой. KERN пишет: `amount = 0, было 0, стало 1`.
3. **Мухлёж в тестах.** ИИ не смог починить баг и написал `except: pass` или `skip`.
   `pytest` показывает зелёное. KERN пишет: `CHEAT DETECTED`.

## Команда 1. «Что у меня в проекте и где он может упасть»

```bash
./kerna путь/к/проекту
```

Ничего размечать не нужно. KERN сам находит исходники, тесты и контракты.

Что вы увидите (реальный вывод на учебном проекте из двух функций):

```
инвентарь : исходников 3 | тестов 1 | MCP-конфигов 0
охват     : просканировано 3 из 3 (ПОЛНЫЙ)
рентген   : функций 5 | проверено 1 | тривиальных 4 | пропущено 0 | находок 1
контракты : файлов с @kern: 1 | доказано 1 | опровергнуто 0
анти-чит  : проверено тестов 1 | сигналов 2

НАХОДКИ:
  - [CRASH PATH] bank.py: average: строка 5 — возможно деление на ноль: count == 0
```

Читается так: **«в файле `bank.py`, функция `average`, на строке 5 будет деление на ноль,
если `count == 0`»**. Это не догадка: число `count == 0` — то, что нашёл решатель.

## Команда 2. «ИИ переписал код — не сломал ли он логику»

```bash
./kerna --delta старая_папка/ новая_папка/
```

Сравнивает две версии одной и той же функции и печатает, **на каком входе поведение
изменилось**. Реальный вывод:

```
поведенческая дельта: изменившихся файлов 1, сравнено 1
СЕМАНТИЧЕСКОЕ РАСХОЖДЕНИЕ (DIVERGED) — 1:
  ~ fee.py: [DIVERGED] fee: РЕФАКТОРИНГ ИЗМЕНИЛ ПОВЕДЕНИЕ
            [КОНТРПРИМЕР] amount = 0, res_old = 0, res_new = 1
```

То есть: «при `amount = 0` старая версия вернула `0`, новая — `1`».

Два важных правила:

* `rc=0` — **новых опасных находок нет** (краши, переполнения, выходы за границы).
* Изменение поведения — это **и баг, и починка**, поэтому по умолчанию оно показывается,
  но не блокирует. Хотите блокировать любое изменение поведения — добавьте
  `--block-on-diverged`.
* Если инструмент **не смог** сравнить (нет решателя, файл не того языка), он говорит об
  этом прямо и **не** пишет «поведение то же».

## Команда 3. «Не сжульничал ли ИИ в моих тестах»

```bash
./kerna --anti-cheat test_my_project.py
```

Реальный вывод на тесте с двумя уловками:

```
[CHEAT DETECTED: swallowed exception (except: pass)] строка 7
[CHEAT DETECTED: unconditional skip inside a test: self.skipTest()] строка 11
[ANTI-CHEAT SUMMARY] файл test_my_project.py: находок 2
```

`rc=1` — есть находки. Ловятся: проглоченное исключение, `skip`, подмена функции
пустышкой, `sys.exit` внутри теста, «зелёный» тест без проверок.

## Команда 4. «Хочу гарантию для важной функции»

Пишете над функцией два комментария — что верно **на входе** и что должно быть верно
**на выходе**:

```python
# @kern:requires balance >= 0 and amount >= 0 and amount <= balance
# @kern:ensures result >= 0 and result <= balance
def withdraw(balance, amount):
    return balance - amount
```

Запускаете:

```bash
python3 tools/kern_contracts.py my_file.py
```

Реальный вывод:

```
[PASS] withdraw: ДОКАЗАНО
       [PROOF VERIFIED] steps: 46 | trusted: 0 | holes: 0
```

`trusted: 0` — важно: KERN **не верит решателю на слово**, он перепроверяет сам вывод и
показывает, сколько шагов проверил и сколько осталось непроверенных (`0`).

Если правило нарушено, вы получите не «FAIL», а **взлом**:

```
[FAIL] withdraw: КОНТРАКТ НАРУШЕН
       [КОНТРПРИМЕР] balance = 0, amount = 1, result = -1
```

Плюс можно попросить готовый падающий тест: `--emit-pytest` — он генерирует файл, который
**реально падает** на этом входе (а не `assert True`).

## Команда 5. «Один закон на весь проект» — `KERN.md`

Вместо флагов и комментариев в каждом файле — **один текстовый файл в корне проекта**:

```markdown
# Контракт проекта
- require_all_functions_covered: true
- tests: tests/

### bank.py :: withdraw(balance, amount)
- requires: balance >= 0 and amount >= 0 and amount <= balance
- ensures: result >= 0 and result <= balance
```

Запуск: `python3 tools/project_spec.py путь/к/проекту` (черновик: `--init`).
Исходники **не меняются**: контракт подставляется во временную копию файла.

Четыре исхода — как в решётке Белнапа:
| исход | что значит |
|:--|:--|
| `[T]` | закон доказан (`trusted: 0`) |
| `[F]` | закон нарушен, печатается контрпример |
| `[B]` | **тесты проекта зелёные, а закон нарушен** — конфликт |
| `[N]` | функции нет в законе (**ничего не упущено**) |

Реальный вывод на демо-проекте, где ИИ добавил лишнюю функцию:

```
  [T] ДОКАЗАНО: bank.py :: withdraw
  [B] КОНФЛИКТ: bank.py :: fee — тесты проекта ЗЕЛЁНЫЕ, а закон нарушен (amount = 0)
  [N] НЕ ОПИСАНА В KERN.md: bank.py :: backdoor_transfer
  ИТОГ: T 1 | F 0 | B 1 | N(в законе) 0 | не описано 1
```

После починки и описания функции: **`ЗАКОН ПРОЕКТА ВЫПОЛНЕН` (`rc=0`)**.

## Где это применять

* **У себя.** Перед сохранением кода, который написал ИИ: команда 1 + команда 3.
* **В GitHub.** Добавить `kern-action` в репозиторий — и на каждом Pull Request KERN сам
  считает дельту и рисует замечание **под строкой кода** (SARIF 2.1.0). Если ваш PR внёс
  баг, он блокируется; если починил — проходит.
* **Для чужого кода.** Скачали репозиторий → команда 1 → за минуту видно опасные места,
  без чтения тысяч строк.

---

## Три честных предупреждения

1. **Не всё доказуемо.** Целая арифметика, битовые векторы, массивы — да. Нелинейная
   математика (`a*b` двух переменных), дробные числа и длинные строки — KERN скажет
   «вне модели», а не «доказано». Это записано в `LIMITS.md`.
2. **Ноль находок ≠ «кода без багов».** Это значит «в том подмножестве, которое KERN
   умеет, проблем не найдено».
3. **Изменение поведения не всегда баг.** Поэтому команда 2 по умолчанию показывает, а
   не блокирует.

## Шпаргалка

| Хочу | Команда |
|:--|:--|
| Найти опасные места в проекте | `./kerna папка/` |
| Проверить, не сломал ли ИИ логику | `./kerna --delta старое/ новое/` |
| Поймать мухлёж в тестах | `./kerna --anti-cheat тест.py` |
| Получить гарантию для функции | контракт `@kern:` + `kern_contracts.py файл` |
| Проверить, что архив целый | `sha256sum -c SHA256SUMS` |
| Убедиться, что окружение в порядке | `./kerna doctor` |

## ДВА РЕЖИМА: не путать (важно)

| | Доказательный | Обзорный `--xray` |
|:--|:--|:--|
| Вход | функция **+ закон** (`@kern:requires`/`@kern:ensures`) | функция **без закона** |
| Вердикт | `ДОКАЗАНО` / `КОНТРАКТ НАРУШЕН` + контрпример | «возможно» + контрпример |
| Это баг? | да (закон нарушен) | **нет** — подсказка о скрытом предусловии |

Пошаговая экскурсия с реальными выводами: **`docs/АНАТОМИЯ_ДОКАЗАТЕЛЬСТВА.md`**.
Апстрим-заявка возможна только при воспроизведении ПУБЛИЧНЫМ вызовом на нормальном входе.

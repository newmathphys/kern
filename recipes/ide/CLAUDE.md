# CLAUDE.md — правила работы с KERN

Этот репозиторий содержит формальный верификатор KERN: он доказывает утверждения
о коде (SMT/Z3 + независимый пруф-чекер), а не «прогоняет тесты».

## Что делать перед тем, как считать правку готовой

1. Если правишь функцию с контрактом `@kern:requires` / `@kern:ensures` —
   прогони `python3 tools/kern_contracts.py <файл>` и добейся `PROVEN`.
2. Если правишь Rust с `derive(PartialOrd)`/`derive(Hash)` на числовых типах —
   прогони `python3 tools/law_hunter.py --rust <каталог>` (0 находок или разбор каждой).
3. Любая находка на публичном API обязана воспроизводиться одной строкой импорта
   и живым падением (компилятор или `python3`), иначе это не находка.

## Чего не делать

- Не публикуй ссылки на этот репозиторий в чужих трекерах: отчёт должен стоять
  на фактах (код, тест, лог), а не на рекламе.
- Не отправляй находку без проверки дублей в трекере проекта
  (`gh issue list -R <owner>/<repo> -s all -S "<ключ>"`).
- Не «улучшай» тест под результат: если тест краснеет — разбирайся, почему.

## Полезные команды

```bash
python3 tools/law_hunter.py --selftest      # законы: 17 точек
python3 tools/kern_contracts.py FILE        # контракты в комментариях
python3 tools/cloud_deep_hunt.py --shard 0 --of 6 --dry-run   # ночная охота
```

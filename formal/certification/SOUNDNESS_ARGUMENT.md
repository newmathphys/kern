# KERN — Доказательство надёжности (Soundness Argument)

> Назначение: DO-333 (Formal Methods Supplement) / ISO 26262-8.
> Вопрос, на который отвечает документ: **может ли KERN сказать «ДОКАЗАНО»,
> когда на самом деле это не так?** (т.е. допустить false negative вердикта).

**Версия:** v1.3 · **Дата:** 2026-10-11

---

## 1. Главный инвариант безопасности (Safety Invariant)

> **INV-1 (Fail-Closed).** `e = 1` (допуск) выдаётся ТОЛЬКО при выполнении
> ВСЕХ условий одновременно:
> 1. `checker_id` разрешён политикой (`VerificationPolicy.allows`);
> 2. дайджест AST совпал (`AstHashMismatch` иначе);
> 3. дайджест контракта совпал (`ContractHashMismatch` иначе);
> 4. вердикт внешнего чекера — строго `Proved`;
> 5. анти-вакуумность не нарушена (`VacuousPrecondition` + политика → отказ).
>
> Любое сомнение (`Unknown`, `Timeout`, `ToolError`, отсутствие решателя)
> приводит к **`e = 0`**. Отказ БЕЗОПАСЕН.

**Аргумент:** условие (4) выполняется только кодом `TrustedChecker.run`,
который в проде запускает изолированный процесс решателя. Функция
`runTrustedChecker` (читавшая вердикт из байта `payload[0]`, т.е. из данных,
управляемых ИИ) **удалена** — см. `src/verifier/admission_gate.zig:148`.

**Свидетельство:** `src/tests/exhaustive_suite.zig :: ФИКС АТАКИ 1:
ОДИН БАЙТ 0xAA НЕ даёт e=1` — прогон: `e = 0`.

## 2. Отсутствие ложного «ДОКАЗАНО» на уровне SMT

Верификатор делегирует математику внешнему решателю. Риск: ошибка
**трансляции** контракта в SMT-LIB (не сам решатель).

| Угроза | Контрмера | Свидетельство |
|:--|:--|:--|
| Ошибка Z3 (заводской баг) | Независимый кросс-чек вторым решателем (cvc5) | `tools/solver_crosscheck.py` — 9/9, 0 расхождений |
| Загрязнение контекста между проверками | `push/pop`-изоляция | `src/tests/smt_incremental_test.zig` |
| Вакуумное предусловие принимается за доказательство | Анти-вакуумный шлюз (`∃x. pre(x)`) | `AI-03`, `MC/DC-6`, `MC/DC-7` |
| Таймаут принимается за опровержение | `Timeout → N`, не `F` | `RES-01` |
| Выход за границы типа (ℤ vs i32) | Формально доказанный разрыв | `formal/KernSemanticGap.lean` (8 теорем) |

## 4. Отсутствие неопределённого поведения (UB)

Скорость (51 ГБ/с) достигнута в `ReleaseFast`, где Zig отключает
рантайм-проверки. Чтобы доказать, что это НЕ за счёт скрытого UB:

* весь сьют прогоняется в `ReleaseSafe` (границы/переполнения активны);
* прогон: `zig test -O ReleaseSafe src/test_root.zig` → **134/134 OK**;
* отдельно — инъекция аппаратных сбоев: `zig build test-fault` → 3/3.

## 6. Границы применимости (честно)

**Что НЕ доказано в v1.3:**

1. **Binary-level soundness.** Lean доказывает математику, Zig компилирует в
   LLVM IR, LLVM — в машинный код. Ошибка оптимизатора LLVM теоретически
   может сломать инвариант. Translation validation (как в seL4) — вне объёма.
   *Частичная мера:* сборка воспроизводима бит-в-бит (`TOR-BUILD-002`),
   тесты проходят в `ReleaseSafe`.
2. **Аппаратный корень доверия.** Аттестация реализована программно
   (Ed25519). TPM 2.0 / SGX / Nitro не используются (нет железа).
3. **Сам Z3 не верифицирован.** Компенсация — кросс-чек вторым решателем.
   Полный proof-checking сертификатов (`get-proof` → Alethe/LFSC) не реализован.
4. **Покрытие MC/DC** подтверждено тест-векторами на решения Врат, но не
   инструментальным LLVM-профайлером (Zig 0.13 не поддерживает
   source-based coverage).

## 7. Заключение

Для класса задач «не пропустить недоказанное» (fail-closed) KERN **надёжен**:
все пути сомнения ведут к `e = 0`, что подтверждено 188 тестами ядра (плюс 25 KERN-Next),
7 файлами Lean 4 (0 `sorry`) и независимым кросс-чеком решателей.

Границы (раздел 6) зафиксированы явно и не замалчиваются.

# KERN — РЕЕСТР ОГРАНИЧЕНИЙ (Known Limitations / Defect Catalog)

> Признак зрелой инженерии — **открытое** описание границ применимости.
> Здесь перечислено то, чего KERN **не** делает, и при каких условиях
> результаты могут быть неполными. Ни одна строка не является «отговоркой»:
> у каждого ограничения указано, как его обнаружить.
>
> Формат: DO-330 TQL-1 / ISO 26262 TCL-1 (реестр ограничений инструмента).

---

## A. Ограничения по методам доказательства

| # | Ограничение | Что это значит | Как обнаружить |
|:--:|:--|:--|:--|
| A1 | **Z3 — не верифицирован формально** | KERN доверяет вердиктам Z3 (`unsat`/`sat`). Баг в самом Z3 → ложный вердикт | `tools/solver_crosscheck.py` (сверка с cvc5) |
| A2 | **Proof-checker неполный** | `proof_check.zig` проверяет наличие вывода `(get-proof)`, но **не каждый шаг дедукции** (не полный Alethe/LFSC) | см. `src/verifier/proof_check.zig`, шапка файла |
| A3 | **Нелинейная вещественная арифметика** | Z3 неполон для QF_NRA: возможен ответ `unknown` → трактуется как `e=0` (безопасно) | `src/verifier/nra_quant.zig` |
| A4 | **Кванторы** | Для формул с `forall`/`exists` возможен `unknown`/таймаут | `src/verifier/nra_quant.zig` |
| A5 | **Рекурсия/циклы** | Глубина обхода ограничена топливом (`fuel`). Циклы доказываются через CHC, но не любой формы | `src/verifier/chc.zig`, `src/runtime/kern_x.zig` |
| A6 | **Абстрактная интерпретация — интервалы** | Домен — только интервалы (не октаэдры/полиэдры): теряет корреляции между переменными | `src/verifier/abstract_interp.zig` |

## B. Ограничения формата и целостности

| # | Ограничение | Что это значит | Как обнаружить |
|:--:|:--|:--|:--|
| B1 | **Merkle покрывает только таблицу** | Подмена **содержимого** ловится отдельной сверкой `SHA-256(payload) == digest`, а не деревом | тест `ФИКС ЦЕЛОСТНОСТИ: подмена payload отвергается` |
| B2 | **Сжатие не реализовано** | `compression_codec` зарезервирован; ветка `!= 0` недостижима | `grep compression_codec src/core/` |
| B3 | **`hash_algo` = SHA-256** | Спецификация упоминает BLAKE3; реализация — SHA-256 (один алгоритм для сквозной сверки) | поле 20..24 заголовка |
| B4 | **Нет контроля версии схемы объектов** | `schema_version` объекта читается, но не валидируется | `src/core/object_entry.zig` |
| B5 | **Лимит размера артефакта** | Файл > 1 МБ в `kernc build` → пустой объект + предупреждение | вывод `kernc build` |

## C. Ограничения производительности

| # | Ограничение | Значение | Как обнаружить |
|:--:|:--|:--|:--|
| C1 | **Безопасное чтение в 330× медленнее RAW** | RAW 55–76 ГБ/с против 164–231 МБ/с (+SHA-256) | `make perf` |
| C2 | **SHA-256 — программный** | Аппаратный SHA-NI не задействован (Zig std) | `src/core/kernfs_router.zig` |
| C3 | **Числа нестабильны** | Разброс ±30% от турбобуста/нагрузки — фиксировать диапазон, не точку | 3 прогона `make perf` |
| C4 | **Merkle O(N)** | Однократное построение корня — линейное (не потоковое) | `src/core/object_entry.zig` |

## D. Ограничения анализа безопасности

| # | Ограничение | Что это значит | Как обнаружить |
|:--:|:--|:--|:--|
| D1 | **QuixBugs — исполнение, не доказательство** | Баги ловятся прогоном тест-кейсов; нет тест-кейса → нет обнаружения | `tools/quixbugs_full.py` |
| D2 | **Статический гейт не улучшает pass@1** | Точность блокировок 100%, но pass@1 не растёт (0.524 → 0.524) | `docs/CAPABILITIES.md` §3 |
| D3 | **Constant-time: порог 3.0×** | Замер ~1.0×, но тест допускает до 3× (шум планировщика) | `src/verifier/noninterference.zig` |
| D4 | **ReDoS-анализ эвристический** | Ловит вложенные квантификаторы, но не все формы катастрофического бэктрекинга | `src/verifier/redos.zig` |
| D5 | **Litmus — эмпирический** | 0 запрещённых исходов на реальном железе ≠ доказательство для всех моделей памяти | `src/tests/litmus_memory_test.zig` |
| D6 | **CyberSecEval 8.0%** | Простые AST-правила; полноценный taint требует Semgrep-уровня | `tools/cyberseceval_check.py` |

## E. Ограничения окружения

| # | Ограничение | Что это значит |
|:--:|:--|:--|
| E1 | **Z3 нужен в PATH** | Без `z3-solver` Врата деградируют в `e=0` (безопасно, но не доказывают) |
| E2 | **`libsqlite3`** | Единственная системная зависимость KERN-Next |
| E3 | **Lean 4 + Mathlib** | Формальные доказательства требуют elan/Mathlib |
| E4 | **QEMU для кросс-арх** | ARM64/PPC64 проверяются через `qemu-user-static` |
| E5 | **Dockerfile не проверен** | Сборка образа не выполнялась (в окружении нет docker) |

## Правило KERN при неопределённости

Во **всех** случаях из списков выше поведение системы — **fail-closed**:

| Ситуация | Результат |
|:--|:--|
| Решатель недоступен | `ToolError` → `e = 0` |
| Таймаут решателя | `e = 0` (жёсткий таймаут, поток-убийца) |
| `unknown` от Z3 | `e = 0` |
| Крах подпроцесса решателя | KERN жив, `e = 0` |
| Нет контракта у заявления | `e = 0` |

> **Ни одно ограничение не приводит к ложному `e = 1`.**
> Это проверяется тестами `z3_crash_test`, `smt_stress`, `mcdc_gates_test`.

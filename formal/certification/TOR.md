# KERN — TOR: Tool Operational Requirements

> Формальный каталог требований к инструменту. Формат DO-330 (TQL-1) /
> ISO 26262-8 (TCL-1). Каждое требование имеет атомарный идентификатор и
> **обязано** иметь проверяемое свидетельство — иначе оно не считается
> выполненным.
>
> **Реестр требований (53 шт.):** [`TRACEABILITY_MATRIX.md`](TRACEABILITY_MATRIX.md)
> · машиночитаемо: [`TRACEABILITY_MATRIX.csv`](TRACEABILITY_MATRIX.csv)

---

## 1. Назначение инструмента (Intended Use)

| Поле | Значение |
|:--|:--|
| **Наименование** | KERN — ядро проверки истины для ИИ-агентов |
| **Класс инструмента** | Верификатор / арбитражный шлюз (Admission Gate) |
| **Назначение** | Присваивать утверждениям статус «доказано» **только** при машинной опоре |
| **Входы** | `.kern` (декларации), `.smt2` (контракты), `.kimg` (образы), `.lean` (теоремы) |
| **Выходы** | вердикт `e ∈ {0,1}` + статус Белнапа `∈ {N,T,F,B}` |
| **Границы применимости** | см. [`KNOWN_LIMITATIONS.md`](KNOWN_LIMITATIONS.md) |
| **Уровень доверия** | TQL-1 / TCL-1: отказ инструмента может привести к **ложному допуску** |
| **Ключевое свойство** | **fail-closed**: любая неопределённость → `e = 0` |

### Что KERN НЕ делает (границы)
* не генерирует доказательства «из воздуха» — только проверяет предъявленные;
* не заменяет компилятор — работает с контрактами и образами доказательств;
* не доверяет тексту: заявление без машинного контракта → `e = 0`.

## 2. Требования верхнего уровня

| ID | Требование | Критерий приёмки |
|:--|:--|:--|
| TOR-SCOPE-01 | Вердикт `e=1` присваивается **только** при машинной опоре | ни один тест не открывает Врата без вердикта решателя/прогона |
| TOR-SCOPE-02 | Неопределённость трактуется как `e=0` (fail-closed) | `z3_crash_test`, `smt_stress`, таймаут-тесты |
| TOR-SCOPE-03 | Заявление без контракта остаётся `e=0` | `kernc verify` на образе без контрактов |
| TOR-SCOPE-04 | Результат **воспроизводим**: одинаковый вход → одинаковый вердикт | снапшоты детерминированы, кэш ключуется хэшем |

## 3. Категории требований (53)

| Категория | Требований | Что покрывает |
|:--|--:|:--|
| `TOR-BEL` — формальная основа | 5 | решётка Белнапа B₄, де Морган, JOIN_K, изоляция конфликта, анти-вакуум |
| `TOR-GATE` — Врата Истины | 7 | вердикт только от внешнего чекера, привязка сертификата, политика, маска чекеров |
| `TOR-KIMG` — формат образа | 7 | заголовок 128 б, дескриптор 96 б, Merkle, безопасная арифметика, версия/алгоритм |
| `TOR-FS` — виртуальная ФС | 3 | валидация путей, NUL-инъекция, запрет записи |
| `TOR-SMT` — SMT-мост и теории | — | graceful-отказ, таймаут, 5 теорий (UNSAT-core, QF_AX, CHC, QF_S, CEGIS) |
| `TOR-CACHE` — кэш доказательств | 4 | детерминизм ключа, эвикция, single-flight, потокобезопасность |
| `TOR-RES` — ресурсы ОС | — | 0 утечек FD, 0 зомби, таймаут решателя, SIGBUS |
| `TOR-SEC` — безопасность и авторство | — | подмена payload, аттестация Ed25519, токен авторства |
| `TOR-BUILD` — воспроизводимость | 4 | сборка, детерминированная сборка, кросс-архитектура, герметичность |

> Точное число по каждой категории — в CSV (колонка `category`).

## 4. Правило трассируемости

**Ни одно требование не может существовать без проверяющего теста.**

Проверка выполняется автоматически:
```bash
make cert          # список документов + число требований
python3 - <<'PY'   # все ссылки на тесты существуют?
import re, os
s = open('formal/certification/TRACEABILITY_MATRIX.md', encoding='utf-8').read()
for path, name in re.findall(r'`([^`]+\.(?:zig|lean|sh))`\s*::\s*`([^`]+)`', s):
    assert os.path.exists(path), path
print("все ссылки валидны")
PY
```

**Текущий статус:** 53 требования, 31 ссылка на тесты — **все ссылки проверены
на существование** (см. `docs/ATTESTATION_PASSPORT.md` §7).
